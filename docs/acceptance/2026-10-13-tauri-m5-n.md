## 1. 这条链长什么样（为什么它比 M5-B / M5-C 各自那条长）

一次进程里串起 扫描 → 重复检测 → 勾一组 → 地图右键加入 → 摘掉 → 换成组内那份 → 预览 → 确认回执。
全程零删除：一个执行入口都不点，跑完逐名点名三个夹具文件仍在盘上、字节数一字未改。

| 相 | 勾选内容 | 期望（PowerShell 自己算） | 修前实测 | 修后实测 |
| --- | --- | --- | --- | --- |
| P0 | 只勾重复组 | 5.0 MB / 1 个文件 | 5.0 MB / 1 ✅ | 5.0 MB / 1 ✅ |
| P1 | 组 + **组外**一个文件 | 8.0 MB / 2 个文件 | 8.0 MB / 2 ✅ | 8.0 MB / 2 ✅ |
| P2 | 组 + **组里那份待删** | 5.0 MB / 1 个文件 | **10.0 MB / 2 ❌ 且 0 条拒绝** | 5.0 MB / 1 ✅ · 1 条拒绝 |

三相的数刻意互不相同（5 / 8 / 10 MB），所以"预览还没重算完"这种过期读数不可能伪装成任何一相的期望值；
取数前还等它自己稳定（连续两次读数一致）。

### 夹具让两条通道落在同一个文件上

```
D:\dc-m5n-fixture\TEMP\dup-a.bin   5 MiB  内容 X   mtime 2020-01-01   ← 定序上该保留
D:\dc-m5n-fixture\TEMP\dup-b.bin   5 MiB  内容 X   mtime 2025-06-15   ← 待删那一份 = §12 要点的那一格
D:\dc-m5n-fixture\TEMP\solo.bin    3 MiB  内容 Y                      ← 不参与任何组，给 P1 当"组外"
DC_ENV_ROOT=D:\dc-m5n-fixture   ⇒ %TEMP% 指到这棵树下（`windows-temp` 的地盘）
DC_AUTOSCAN=D:\dc-m5n-fixture\TEMP ⇒ 扫的就是那层，三个文件都是根层格子，归属必命中
```

三条独立坐标，都不读被测代码：
① 期望字节由 `Get-FileHash` 认组、`LastWriteTime` 认"留哪份"现算；
② **界面自己念出的**保留 = `dup-a.bin`、待删 = `dup-b.bin`，与 ① 逐字一致（这一条同时钉住了
   「保留哪一份」不是我猜的）；
③ 跑完逐名点名盘上还在不在。

### 地图那一格怎么"点得准"

Treemap 是 canvas 自绘，格子不在 UIA 树里，元素矩形在 WebView2 里也不可信。所以
**"点中了哪一格"不由像素判定**：先单击一个比例坐标，读**详情面板里那条完整路径**（M5-C 修好的
那个 `path` 载荷），确认是目标才在同一点右键，再按名字 Invoke 菜单第五项。
「空间地图」这四个字在清理页那句「从空间地图加入的」里也有 ⇒ 判"到了地图页"用的是
**「预计释放」消失**，不是"找得到那四个字"。

## 2. 缺陷的机制（一句话：那句注释的前提是假的）

`crates/cleaner/src/preview.rs` 里全局去重那张表原本写着：

> 全局去重：同一路径在整个预览里只计一次钱（**引擎的 claimed 表已保证**，这是第二道保险）

claimed 表只保证**登记表规则**之间一条路径只有一个主人。§20 的伪项（`rule_id = "dup:" + 组 id`）
**不参与那张表** —— 它的一份待删路径完全可以同时是某条规则地盘里的文件，也就是同时被
§12 的逐路径勾选表达一次。而整项勾选那一支直接 `bytes = f.total_bytes`，从不往
`priced_keys` 里看、也从不往里记账，于是：

- 同一条路径计两次钱、文件数也计两次；
- **一条拒绝都不留**（第二次表达既没计价也没点名 ⇒ 界面上没有任何东西会提示用户"这两个数是同一个文件"）。

方向是**虚高**不是多删：工作单侧 `executable_paths` 走 `sort + dedup`，盘上只会少一次。
坏的是 §19 那句「预估 = 实删」—— 量到差额正好等于那个文件的字节数。

原有三条单元判据为什么没抓住：`whole_item_then_paths_does_not_double_price` 是**同一条规则**的
整项 + 逐路径，`the_same_path_under_two_rules_is_priced_once` 是**两边都按路径勾**。
"整项 × 逐路径 跨两条规则撞同一条路径"这一格从来没有用例 —— 这正是 M5-M 说"只有代码级证据"时
高估了的那份证据。

## 3. 修在哪一层

判据层（`build_preview_model` 的 `if whole` 一支），不在界面打补丁：

- 整项勾选现在把它认领的**每一条路径**交进全局 `priced_keys`；
- 撞上已经计过钱的那条 ⇒ 从自己的价里扣掉（`saturating_sub`）、文件数减一，并留一条
  `duplicate-selection` 点名；
- 反序也成立（整项先计价 ⇒ 后来那条逐路径被拒、该行不再计入）。

三条新用例（`crates/cleaner/src/preview.rs` 的 tests）：

| 用例 | 钉的是 |
| --- | --- |
| `a_path_priced_by_tile_then_covered_by_a_whole_item_is_priced_once` | 逐路径先、整项让位（P2 的真实次序） |
| `a_whole_item_priced_first_lets_no_other_item_price_its_paths_again` | 反序 —— 两条用例是两个轴 |
| `a_whole_item_without_a_full_list_is_not_pretended_to_be_deduped` | **边界**：没有全量清单就不假装去重（钉"本模块不覆盖这一格"，不是"它也去重了"） |

**变异证明**：把整项那一段换成不可达（`f.all_paths.as_ref().filter(|_| false)`）⇒
前两条当场红（`left: 200 right: 100`，正是真机那个双计形状），第三条照旧绿（它本来就不依赖这段）；
还原后与还原前逐字节 `cmp` 相同，18 条 preview 用例全绿。

修后界面的读法（`assets/m5n-03-overlap.png`）：`重复文件 · dup-a.bin 等 2 份` 那一行
**占用 5.0 MB / 计入预估 0 B**，地图那格 5.0 MB 拿到唯一一次计价，合计 `5.0 MB 预计释放 · 1 个文件`，
页脚 `被拒的勾选（1 条，逐条点名）`，回执 `已确认 2 项 / 1 个文件 / 5.0 MB（指纹 acb4cf56fb2e4440）`。

修前那一屏留在 `assets/m5n-before-fix-double-count.png`（修前那次跑完全部四相、只在末尾判据上红，
所以它的收尾截图就是缺陷本体）：同一行显示 `占用 5.0 MB / 计入预估 5.0 MB`，合计
`10.0 MB 预计释放 · 2 个文件`，风险分账 `🟢 安全 5.0 MB/1 文件` 与 `🟠 高风险 5.0 MB/1 文件` 各占一份，
**页面上根本没有「被拒的勾选」那一栏**（零留痕的可见形态），而回执是
`已确认 2 项 / 2 个文件 / 10.0 MB（指纹 ca14a89d174751bf）` —— 也就是说 §18 的通行证
本身就锚在一个盘上兑现不了的数上（Rust 侧工作单会 dedup 成 1 条 5 MiB，§19 于是必然报出 5 MiB 差额）。

> 顺带把一条判据的分辨力补上了：`被拒的勾选（N 条 …）` 那个计数器在修之前**三相都读 0**，
> 当时分不清"真没有拒绝"与"我的正则抓不到"。修后它读出 1 ⇒ 这个计数器证明了自己非零命中。

## 4. 与 TS 的分叉：人类伙伴裁定「只修 Rust 侧」

`core/rules/preview.ts` 的 `if (whole)` 与 Rust 改前逐字同形 ⇒ 这是两侧共同的缺口。
裁定（2026-10-13 当场选）：**只修 Rust，Electron 那半（在发行的产品）故意不动。**

代价，逐条写清：

1. **Electron 版仍然会双计**，§19「预估 = 实删」在那一侧目前不成立（方向虚高，不多删）。
2. **跨语言零容差对账从此在这一格失去覆盖**。M3-B 的预览对账夹具**刻意不含**这一形制 ——
   这一点写进了 `crates/cleaner/tests/preview_parity.rs` 的文件头，并写明"往里加这种 case
   必然红，而那条红是分叉本身，不是 Rust 算错了"。`core/rules/preview.ts` 的对应位置也留了反向指针。
3. **现有 golden 一字未动**（两条对账测试修后都绿：
   `the_rust_preview_agrees_with_the_ts_preview_on_the_shared_fixture` /
   `the_rust_gate_agrees_with_the_ts_gate_on_the_shared_fixture`）—— 因为夹具里确实没有这一形制，
   这是"没打到"而不是"打到了还相等"。
