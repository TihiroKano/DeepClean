## 1. 主线：那格 `logPath` 现在是真路径

基准是两处：`electron/main/logger.ts:14` 的 `formatLogLine`（线格式）与
`core/clean/executor.ts` 的 §29 注入面（每一次删除、每一条拒绝各一行）。
Rust 侧原来两处都没有 —— `JournalPage.log_path` 恒 `None`，于是记录页页脚那句
「（本次会话没能确定日志文件路径）」成了长期状态。

| 新/改 | 内容 |
| --- | --- |
| `crates/cleaner/src/logline.rs`（新） | `format_log_line` / `LogValue` / `CleanLog` / `local_stamp`，9 条判据 |
| `crates/cleaner/src/executor.rs` | `ExecuteCtx.log: Option<Arc<dyn CleanLog>>` + 7 个事件点（start / 每条 refused / file×2 / dir×2 / end×2） |
| `src-tauri/src/cleanlog.rs`（新） | 文件 sink：`%APPDATA%\com.deepclean.app\logs\deepclean.log`，追加、写坏一次就 latch off，4 条判据 |
| `src-tauri/src/service.rs` | `init_clean_log` 在 `setup` 里挂；`execute_plan` 把 sink 注进 ctx；`journal_query` 那格从 `None` 换成真路径 |
| `crates/cleaner/src/lib.rs` | `logline.rs` 进零删除静态名单，**并补上一直没在名单里的 `journal_view.rs`** |

三个设计决定，都是照抄基准而不是自己发明：

1. **字段是有序串表，不是 struct** —— 线格式就是 `k=v` 按声明顺序拼接，`undefined` 那格
   **整段不出现**（不是 `k=`）。用 struct 表达会把"顺序也是格式"这件事藏起来。
2. **日志不参与判定** —— 写坏了只是不再写，不拦删除（基准同样）。这条有专门的判据：
   `attaching_a_logger_changes_nothing_about_the_outcome` 比的是**序列化后的任务形状**逐字节相同。
   反过来做（"日志写不下去就不许删"）看着更安全，实际会把"磁盘满"变成"清理点不动"，
   而那个症状与闸被绕过长得一模一样，只是方向相反。
3. **在删除进行中写，不是事后从 `CleanTask` 摊平** —— 基准那句理由成立：「崩溃时不能丢最后几行」，
   而内存里那本账在崩溃时整个没了，正是这份文件补的位置。

## 2. 缺陷 #1：`local_day` 少一天（用户可见，已修）

`journal_view.rs` 原来的算法是：先按 **UTC** 取日历日，再把「那一天的 00:00 UTC」送去
`SystemTimeToTzSpecificLocalTime`。时分秒被丢掉了，于是**本地时刻落在 `[00:00, 时区偏移)`
那一段的每一个瞬间都少一天**（本机 UTC+8 ⇒ 每天 0 点到 8 点，等于 UTC 16:00–24:00）。

独立口径扫一天 48 个点（`.NET DateTimeOffset.ToLocalTime()`，与 JS `new Date(ms)` 同语义）：
**16 个不符**。

```
MISMATCH ms=1762012800000 utc=2025-11-01 16:00Z local=00:00 correct=2025-11-02 rustLocalDay=2025-11-01
...
checked=48 mismatch=16
```

用户症状就在记录页那一页：**凌晨删的东西，页面显示 10-13，按 10-13 筛回 0 条**
（日期键算成了 10-12，而显示那格是渲染端自己换算的，两边各算一次）。
这一轮真机跑的时刻是 **02:20**，正好整段落在那个窗口里 —— 顺带就是它的活体样本。

修法是换算**那一刻**，并且让日期键与日志时间戳**共用同一份换算**
（新增 `local_system_time`，`local_day` 与 `local_stamp` 都从它出）。各算一次就会有那一天对不上。

新增判据 `a_row_deleted_between_midnight_and_the_utc_offset_is_found_under_its_own_day`：
钉在**筛选这一层**而不是日期算术那一层，期望值 `2026-10-13` 来自
`node -e "new Date(1791829800000)"`。之所以要另起一条：原来那条
「条目自己那一天要能筛出来」两边都调 `local_day` 自己出题，函数错了它照样绿 —— 自证不是验证。

## 3. 缺陷 #2：那条对账的取样资格是假的（判据空转，已修）

`local_day_agrees_with_the_renderers_formatDay` 是 M3 那轮写的**外部口径**对账，
一张 10 点的 node 表。它今天仍然"绿"，但**在这台机器上一次都没跑过**：

```rust
struct TzInfo { bias: u32, ... }          // 真类型是 LONG = i32
let minutes = -((tzi.bias + extra) as i64);
```

`TIME_ZONE_INFORMATION.Bias` 是 **LONG（i32）**，Windows 还是"西为正"——本机 UTC+8 给的是
`-480`。按 `u32` 读它就是 4_294_966_816，取负后 `!= 480` **在任何机器上都恒成立**，
于是那道"这台机器不是那张表的机器就跳过"的闸每次都跳过，而测试打印的是 `ok`。

两个缺陷叠起来的效果是：**#1 一直有一把外部尺子能量到它，但拿着尺子的那道闸自己坏了。**

处置：类型读对；`TIME_ZONE_ID_INVALID` 直接失败而不是当"不匹配"；加一条"读出来的偏移得
像个真偏移（`|x| ≤ 900`）"；再加一条测试专门钉**取样闸自己得能红**。把那张表从 10 点扩到
22 点，横跨本地跨日的那条线（原来 10 个点全在"UTC 上午"，正好绕开出事的 8 个小时）。

四格探针（`D:/dc-tmp/mutc.log`），期望值先写下再跑：

| 编号 | 变异 | 期望 | 实测 |
| --- | --- | --- | --- |
| C1 | 三格 bias 读回 `u32`（两道断言都在） | RED | **RED**（2 条用例红） |
| C2 | 同上 + 拿掉 helper 的资格断言 | RED | **RED**（那张表已经在跳过，是**新那条测试**报的红） |
| C3 | 同上 + 再拿掉测试那句 | GREEN | **GREEN**，`test result: ok. 95 passed`，日志里出现"跳过" |
| C4 | 只拿掉 helper 断言（读是对的） | GREEN | **GREEN**（它今天不在失败路径上，这是诚实结论） |

**C3 那一格就是修前的形态**：95 条全绿、那张 node 表一次没跑、没有任何地方说它没跑。

## 4. 变异电池

驱动在 `D:/dc-tmp/`（版本控制之外）。两张表都是"改坏 → 必须红 → 还原 → 基线复跑绿"。

**A 系列（日期键与线格式，9 条）**：A1 时分秒归零（回到缺陷本身）、A2 干脆不换算、
A3 三格 bias 读成 u32、A5 `local_day` 不走共用原语、A6 引号判据丢掉 `"`、
A7 丢掉 U+FEFF、A8 缺席字段写成 `k=`、A9 时间戳退化成只有日期 → **8 红**；
A4（只拿掉 helper 断言）**绿**，理由见上面 C3/C4 那一格。
A1/A2/A5 现在同时让**筛选层**那条用例红，不只是算术表。

**K 系列（事件、落盘、接线，11 条）**：K1 少 start、K2 字段换序、K3 失败那行不再写量到的
大小、K4 拒绝不写日志、K5 结尾漏 `refused`、K7 记录页那格永远 null、K8 时间戳换成常量、
K9 坏掉的 sink 不再 latch、K10 scope 变 `[Clean]`、K11 append 改成截断重写 → **10 红**；
K6（整批被拦那行改成读 task 计数）**绿** —— 三关没过之前那几个计数本来就是 0，
**读与不读今天不可区分**，所以那格字面量没有判据可钉（已在代码注释里写明，不假装它被验过）。

K8 一开始也是绿的，红的是我自己的判据：那条断言原来写的是 `starts_with("2")`，
把 `local_stamp` 换成常量 `"2026-01-01 00:00:00"` 照样过。改成拿**今天的本地日期**当期望值之后
它才真的抓得住。

## 5. 与基准的两处已知差（登记，不偷偷抹平）

1. **少一个事件点**：基准有 `verify measure failed`（`executor.ts:586`），Rust 侧
   `CleanFs::measure` 回的是 `MeasureResult` 而不是 `Result` —— 那条路在这套接口里不存在。
2. **`ms` 那一格在 Tauri 侧恒为 0**：`started_at_ms` 与 `finished_at_ms` 都取注入的那一个
   `now_ms`（本模块按纪律不读 `SystemTime`），而基准是 `o.nowMs ?? Date.now()` 两头各读一次
   墙钟。要换真值得把"时钟"从一个数改成一个函数，那是执行器契约的改动（几十个
   `with_now_ms(0)` 全跟着动），换的只是日志里一格时长。**别把这格当耗时读**，
   代码注释与这里都写着。

## 8. 没做与代价

1. **`ms` 恒 0**（§5.2）。代价：日志里那一格是装饰性的，读它的人会被误导 —— 已在代码与本文档写明。
2. **少 `verify measure failed` 那一条**（§5.1）。代价：如果以后给 `measure` 加上失败面，
   那个事件点要一起补，否则日志会缺"验证没做成"这一类。
3. **日志没有轮转/上限**。基准也没有（`appendFileSync` 一路追加）。代价：这个文件只增不减，
   长期使用要用户自己删；写坏一次之后整个进程不再写（`broken` latch），也不会在下一次
   启动之前恢复 —— 那时记录页那格仍然报路径，而文件里可能已经没有新行。这一格
   与基准同形（`log.path` 不看 `broken`），所以没动。
4. **记录页的日期筛选没在真机上点**（`<input type="date">` 的段序是区域相关的，UIA 驱动它
   属于"看着能点、点歪了看不出来"那一类）。§2 那条筛选层判据是在单测里用 node 给的
   真时刻钉住的，不是截图验的 —— 这里说清楚，别让读者以为真机点过。
5. **`journal_view.rs` 之前不在零删除静态名单里**，本轮补上（名单少一行与判据失效在结果里
   长得一样，都表现为绿）。
