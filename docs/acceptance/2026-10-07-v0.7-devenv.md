## 偏离清单（各自写明理由与代价，不许被读成"已满足"）

1. **没有 `IDevEnvDetector.scan()`。** 计划书那个接口让探测器自己产出 `DevEnvFinding`。照抄的结果是**同一台机器上两套路径判据**（`registry.ts` 的声明式模板 + 探测器里手搓的 15 条路径），而 §28 原则四的叶子路径判据、防双计的 claimed 表、🔴 四层结构闸全都长在引擎那一侧。正解是探测器只回答"装没装"这一维、地盘仍由规则声明 —— 代价：`isInstalled()` 是同步签名（`probe` 注入）而不是 `Promise<boolean>`，未来若要走真异步发现（如网络盘）得改形状。
2. **`isInstalled()` 不碰注册表**（裁定 2）：命令可用性 + 已知目录存在性两级取或。代价：用图形安装器装完、PATH 里还没有命令、缓存目录也还没生成的那种工具会被判"没装" —— 方向是**少报**，界面上念「未检测到」而不是给一个 0。
3. **§3.3 表里 `__pycache__` / `node_modules` / virtualenv 三项维持不做的原判**（V0.4 定的，本轮不重开）。原因不是"忘了"：声明式路径模板的 `*` 恰好只匹配一层目录名，"任意深度按目录名匹配"表达不出来，硬凑就是假字节数。**这是有意不做，不是漏做。**
4. **Docker 只读 `docker system df`，不做 Engine API。** 计划书 §3.4 两个都列了。选 CLI 的理由：不引入 HTTP 客户端与 named pipe 依赖（本轮零新增依赖），且 `prune` 那类动作本来就该由用户自己在终端执行。代价：daemon 未启动时 CLI 会报错而不是给出 0 —— 这一版把它如实映射成 `unmeasurable`（"量不到"），界面上不印 0 B。
5. **§3.6 的界面是"一行一条规则"，不是计划书草图里"一行一个生态"。** 草图把 `npm cache 2.1GB / pnpm store 3.4GB` 挤在同一行，那样一行的"全选"语义会含混（两个工具装没装是两件事）。改成按生态分组、组内逐条一行。代价：见「未完」第 1 条 —— 草图里 AI 那行的「检测到 3 个大模型文件（共 26GB）」这一格**本轮没做**。
