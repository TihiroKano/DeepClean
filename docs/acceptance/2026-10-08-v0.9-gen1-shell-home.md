## 2. 实测证据（每条都点名是怎么量的）

### 2.1 色板是量出来的，不是目测
`scripts/ui-palette-probe.cjs`：解 PNG 的 IHDR/IDAT、`zlib.inflate`、手工反滤波（filter 0–4），按区域取众数色。
落进 `global.css :root` 的关键值 —— 页底 `#102b5d`、侧栏 `#06245d`、大卡 `#0c2c61`、
右卡 `#1a3d7a`、内嵌子卡 `#193464`、CTA 两端 `#1972fd → #31a9fd`。
**用量条没跟草图**：草图是恒蓝渐变，而这条按占用率变三档（`--usage-low/mid/high`）是真判据，
换成恒蓝等于把信息换成装饰。这条偏离写在 `global.css` 的 token 注释里。

### 2.2 圆角与拖窗（真机，非 `--shot`）
`npx electron .` 起真窗口 → `EnumWindows` 按标题找到 `DeepClean`（pid 6964）→
`SetProcessDPIAware` + `GetWindowRect` + `CopyFromScreen` 抓整窗 → `scripts/ui-corner-probe.cjs` 逐行找产品像素的起点：

```
top-left    0:-1 1:-1 2:20 3:16 4:15 5:14 6:13 7:12 8:12 … 11:11 之后恒 11
bottom-left 0..10:-1 11:20 12:16 13:15 … （右下同理，右边界从 2161 爬到 2170）
```

四角都有这条斜坡，宽度 ~11 物理 px ⇒ **7.3 DIP**，即 DWM 的标准圆角。**草图的 28 px 没拿到，也不打算拿**（U5）。

拖窗：`computer-use` 真实鼠标从窗口相对 (95,520) 拖到 (285,600)，
输入侧报 screen (106,644)→(331,739)，之后 `GetWindowRect` 从 `left=-11 top=44` 变成 `left=325 top=187`
—— **位移 +336,+143 物理 px，与指针位移 +225,+95 DIP × 1.5 = +337,+142 对得上**。
`.dc-side` 的 `-webkit-app-region: drag` 与按钮的 `no-drag` 是真的生效，不是"图上看着能拖"。

### 2.3 让位区（这条抓到了真缺陷）
`--shot` 新增 `checkOverlay()`，在首页 / 地图根层 / 大文件三处，把页面上每个
`button, select, input, a` 的 rect 与右上 138×40 比。**未修之前它是红的**：

```
[shot] §23 标题栏让位区 地图根层 => {"bad":["dc-select@1351,9"],"vw":1440}
[shot] FAIL: §23 标题栏让位区（地图根层）：1 个可交互元素伸进系统按钮区，会被盖住且点不动：dc-select@1351,9
```

处置是给 `.dc-bar` 加 `padding-right: 152px`（一处修好地图/大文件/清理记录三页，它们共用这条栏）。
修后三处 `bad: []`。
**"红→改→绿"这一对就是这条判据的变异证明**，没再另装一次缺陷。

### 2.4 首页五块卡的呈现闸
`--shot` 的 §23 首页那一跑，现值：

```
rects: main 746×415 / side 366×415 / recent 366×233 / quick 366×233 / disks 366×233
paint: 五块全是 {bg:"rgba(12, 44, 97, 0.86)", radius:"20px", opacity:"1", hit:"self"}
tracks: 3   stops: ["rgb(47, 158, 253)","rgb(49, 169, 253)"]   pct: "96.0%"
```

判据分两层，**这个分层是被逼出来的**：先只写了量盒子的那层（rect + 轨道数），
拿 `--glass-fill-card: 0` 去变异，五块卡的盒子尺寸**一个都没变**、判据全绿 ——
只量盒子等于没量。于是补了呈现层：computed background 的 **alpha 数值**（不是字符串比对，
`rgba(12,44,97,0)` 也是全透）、圆角非 0、opacity/visibility、以及中心点
`elementFromPoint` 必须命中自己或后代。变异重跑：

```
[shot] FAIL: §23 首页呈现：main 卡的 background alpha=rgba(12, 44, 97, 0) —— …（五块各一条）
```

`donut` 的两个 `stopColor="var(--accent)"` 也单独钉了一道：Chromium 确实解析（上面那行 `stops` 就是证据），
但不解析时弧会**画了而看不见**，那是 V0.8 地图那族缺陷的形状。

## 3. 被推翻与没证到的

### 3.1 「五块卡只画一块」的归因是错的，真因未找到 ⚠️
第一次真机 `--shot` 的 `02-home-done.png` 上，五块卡只画出来一块（磁盘管理，且被拉得很高）。
我当时判定原因是 `.dc-grid` 两列轨道配了三个区域名 ⇒ 浏览器造隐式列，并当场改成三列版。
**今天把两列那一版原样装回去重跑：五块卡全画出来**，`--shot` 打印
`main 681 / side 432 / recent 337 / quick 330 / disks 432, tracks: 3`，判据零红。
⇒ 隐式列**不是**原因；改完之后的"好了"与那次改动**没有因果关系**。
中间我还同时改了别的（`.dc-ell`→`.dc-trunc`、磁盘行三列改四列、图例点颜色、卡头文案、`BroomIcon`），
**没有做单变量对照，所以现在说不出是哪一处**。
留在生产里的只有：现象真实发生过、当时的 §23 判据抓不到它（那版只量盒子），
而 §2.4 补的呈现层现在抓得到"盒子在但看不见"这一整族。
**这条不是已解决**，下一个看见"卡不见了"的人请从这里继续，别引用我那句隐式列。

### 3.2 图标"逐像素相同"是子代理自导工具量的
`icons.tsx` 里 `CloseIcon`/`BoltIcon`/两条 `Chevron*` 为了满足"≥2 个几何元素"把一笔拆成两笔，
子代理报告说"用描线光栅器比对过 0 像素差"。**那是它自己写的工具给的数，我没独立复现**（见记忆
`feedback-verify-visually-not-by-self-derived-numbers`）。首页截图上这几个形状肉眼没看出断痕，
但这只算"看着还行"，不算证过。

### 3.3 系统按钮本身没做点击测试
只证到：按钮**渲染**出来了（真机截图右上）、我们的内容**不占**那块（§2.3）。
最大化/最小化/关闭是否各自响应，没点过 —— 它们是 OS 画的，且本项目**没开 `transparent`**，
所以"最大化盖任务栏"那一族已知坑结构上不存在。真要收口得补一次 `computer-use` 点击。

### 3.4 `--shot` 崩的时候 `shot-failures.txt` 会写 1，和"真的只红一条"分不开
本轮碰到两次 GPU 进程猝死（`GPU process exited unexpectedly: exit_code=34` →
`capturePage` 抛 `UnknownVizError`），其中一次还连带让地图底色层九点采样报 0 点
（canvas 随 GPU 一起没了，不是产品缺陷）。崩溃路径走
`electron/main/index.ts` 的 catch，写的是**字面量 1**。
所以那一跑的 `failures=1` 底下其实是"5 条判据 + 一次崩溃"。
判崩溃要看日志里有没有 `[shot] failed`，别只看那个数。
