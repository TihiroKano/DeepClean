## 1. 这一棒真正值钱的不是 §12 接通，是它挖出的那个缺陷

第一次真机跑出来是「计入预估 —」，而 `cargo test --workspace` 与 `npm test` **全绿**。
加了一条临时 `eprintln!` 直接看服务端收到什么，答案是：

```
[M5C-DIAG] raw tile_paths = Some([String("")])
```

根因不在 §12 的代码，在 **M2-A 就落库的 `src-tauri/crates/scanner/src/tree_index.rs:249`**：
`to_view` 给文件子项交的 `path` 是 `String::new()`。于是地图右键那四项
（打开 / 打开所在位置 / 复制路径 / **加入清理列表**）对**文件**全拿到空串 ——
症状不是报错，是"点了没反应"。它活了 20 多个里程碑，因为：

- 单测自己拼的是真路径（`temp_path()`），**从没经过那条载荷** ⇒ 夹具的形状不是生产的形状；
- 详情面板显示的是 `name` 不是 `path`，所以肉眼看不出缺了什么；
- 没人拿真文件点过一次那四颗按钮。

修法：`level_of` 把父目录路径传进 `to_view`，文件路径按 `tree_index.rs:344` 已有的那个拼法现拼
（`trim_end_matches('\\')` + `\` + 名字）——  arena 里 `ScanFile` 只存名字是 M2-A 折 arena 时**刻意省的那份开销**，
所以不能改成存全路径。由 `a_file_child_carries_a_full_path_under_its_dir` 钉住：
非空、等于 `父目录\名字`、**不含双分隔符**，并带一条红线哨兵（视图口径怎么改，`Σchildren + folded_bytes == sum_children_of` 不许动）。

## 3. 判据与变异

壳层 4 条：`a_tile_path_is_attributed_by_the_engines_own_claim_table` /
`a_tile_that_no_rule_claimed_is_named_not_guessed` /
`a_tile_merges_into_an_existing_per_path_selection_of_the_same_rule` /
`the_unclaimed_key_is_absent_unless_the_request_asked_for_it`，
外加诊断留下的 `the_claim_table_carries_the_map_path_when_the_scan_root_is_a_parent`
（它钉的是"扫描根是领地的**父目录**"那个真机形状 —— 单测原来用 `%TEMP%` 当根，把这一层差异抹平了）。

变异（第一方跑，`cargo test -p deepclean-app`）：

| 变异 | 红了哪条 |
| --- | --- |
| N1 归属反查永远查不到 | **2 条**（`a_tile_path_is_attributed...` 与 `a_tile_merges_into...`） |
| N2 查不到时不点名 | `a_tile_that_no_rule_claimed_is_named_not_guessed` |
| N4 没问归属也把键挂上线 | `the_unclaimed_key_is_absent_unless_the_request_asked_for_it` |
| **N3 不并入已有的逐路径项** | **红 0 条** ⇒ 见下 |

**N3 红 0 的处置**：模型对同一规则的多条逐路径项取并集，所以"合并"那一段在 Rust 侧与不合并等价。
判据 `a_tile_merges_into...` 保留，但它钉的是**最终计价**（两个文件都算进去、只出一行），
不是那道合并 —— 与 M5-B 那条 `already` 死闸同一处置：**量不出区别的东西不许冒充钉住了**。

桥侧变异 V8（丢 `dupExclusions`）/ V9'（丢 `tilePaths` 转发）各红 2 条 / 1 条（`npx vitest run` 实跑）。

## 4. 真机（`scripts/m5c-tile-e2e.ps1`，exit 0）

夹具在已授权靶场里：`envroot\TEMP\m5c-tile.tmp`（在 `windows-temp` 地盘内）+
`envroot\outside\m5c-stray.bin`（地盘外），`DC_ENV_ROOT` 只重定向规则领地那五个键。

| 坐标 | 界面上 | 图 |
| --- | --- | --- |
| 右键文件 → 菜单 | 六项齐全，「排除该目录」对文件置灰并写「只按目录」 | — |
| ① 点「加入清理列表」 | 「Windows 临时文件」勾选框自动打上 ✓、占用 4.0 KB、文件 1、**计入预估 4.0 KB**、副行「按已枚举路径计价」；页脚「已勾 0 项 · 计入 1 项」「4.0 KB 预计释放 · 1 个文件」 | `m5c-tile-counted.png` |
| ② 对地盘外文件重复 | 「从空间地图加入的 2 个文件」里那条标 **未定价**；下面一句「**其中 1 个不属于任何清理规则的地盘，没有进勾选（归属由规则引擎自己的认领表反查，不靠路径猜）**：…\m5c-stray.bin」；合计仍是 4.0 KB / 1 个文件 | `m5c-tile-unclaimed.png` |
| 零删除 | 两个夹具文件跑完都还在盘上 | — |

**脚本自己踩到的三条**（都写进注释了）：① 这台机器上脚本进程抢不到键盘前台（`SetForegroundWindow`
六次不生效），改用 `SetWindowPos(HWND_TOPMOST)` —— 鼠标事件按坐标投递，要的是"那一点上我们最上面"；
② UIA 元素的 `BoundingRectangle` 在 WebView2 里不可信，拿它的"中心点"点菜单会点到画布上把菜单关掉；
③ 中文码点又写错一个字（「清理预**览**」写成「预**估**」），症状与"页面没渲染"一模一样。
坐标是按窗口比例算的，**点没点中不由像素判断，由点完之后界面必须出现的东西判断**。

## 5. 没做与没验证的

1. 地图右键那四项里，「打开」/「打开所在位置」/「复制路径」在 Tauri 侧仍是 `ni()` 桩
   （`revealInExplorer` / `openItem`）—— 路径现在是真的了，命令还没接（归 M5-E）。
   **这一格现在会抛错，不再静默**，但用户点了仍然没反应。
2. 窗口尺寸变了，脚本的比例坐标会点偏 —— 那时它红在断言上（不会静默拍到别的窗口），但要重跑就得重算。
3. §12 与 §20 同时勾选时的**去重**（同一文件既被整项勾选又被逐路径勾选）由模型的 `duplicate-selection`
   管着，本棒没为这个组合单独写真机用例。
