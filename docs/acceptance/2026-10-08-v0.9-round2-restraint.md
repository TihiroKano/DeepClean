## 1. 这一轮唯一可以机判的那条要求：配比

说明 §13 要 80% 深灰黑 / 15% 白灰 / 5% 蓝。"高级感"量不出来，**但"蓝有没有铺满屏幕"量得出来**，
所以把它做成了一对判据（`--shot` 的 §23 配比，`electron/main/index.ts`）：

```
panelBlue = 主面板 computed background-color 的 (B − R)   必须 ≤ 12
ctaBlue   = 主按钮 computed background-color 的 (B − R)   必须 > 12
```

现跑真值：`{"panelBlue":0,"ctaBlue":168}` —— 面板是**中性**的（白纱玻璃，r=g=b），
蓝落在按钮上。第一代那块 `rgba(12,44,97,.86)` 蓝板子的 `B−R` 是 **85**。

**为什么是一对而不是一条**：只判"面板不许蓝"，把整屏刷成纯灰也能过，而那就丢了品牌强调色；
只判"按钮必须蓝"则管不住背景。两条各钉住配比的一端。

## 2. 窄图标栏（§3）

实测 `.dc-side` 宽 **84 px**（说明要 76–90），导航 7 条 + 栏底「设置」= 8 个按钮，
选中态是 `rgba(255,255,255,.075)` 的轻玻璃胶囊 + 图标染蓝，**没有亮蓝底、没有外发光**。

关键的一条：**中文标签仍然住在 DOM 里**，只是平时 `opacity: 0`、悬停时浮到栏右侧。

② `content` 里的字读屏软件念不出来。
这条约束由 §23 新增的一条判据钉住（`navLabels` 里有空的就红）。

## 3. 首页（§4–§9）

一屏只剩两块面板 + 一条轻带：

| 说明要的 | 落点 | 数据源 |
|---|---|---|
| 顶部「本地磁盘 C:」+ 三个数 | 主面板标题 + 环中心 % + 两个 stat | `DriveInfo.usedBytes/totalBytes` |
| 精致的环形指示器、细线渐变蓝 | `Donut.tsx`：笔画 14→9、半径 62→70、轨道 `rgba(255,255,255,.055)`、渐变 `--accent → --accent-3`、内沿 1 px 高光线 | 同上 |
| Liquid Glass 主按钮 | `.dc-cta`：半透明 + 轻蓝染色 + 上沿高光 + 下沿内阴影 + `0 0 18px rgba(77,143,245,.10)` 边缘光 | `scan.start()`，含运行中/暂停/取消三态 |
| 扫描范围默认不显示大输入框 | 两个 radio，选「指定位置」才出路径框 | 同上 |
| 右侧只有简洁的空间概览 | 四根细条（系统/应用/用户/其他），只有蓝 | `summarizeGroups()` + `toOverviewRows()` |
| 下方一条轻量「最近一次扫描」 | `.dc-recent` 轻带，不是卡 | `ScanSnapshot.finishedAtMs` / `.files` / `reportReclaimableBytes` |
| 磁盘切换走右上角下拉 | 标题行右端的 `<select>` | `scan.drives` |

**撤掉的东西**（都是能力搬家，不是删功能）：「快速入口」六格（把侧栏导航重复了一遍）、
「磁盘管理」三行（与切盘下拉是同一份 `root` state 的两个视图 —— 同屏两个控件写同一个状态，
迟早有一个是错的）、问候语与 46 px 大 logo（品牌位全窗口只留左上角一处）、
「切换磁盘」那颗重复按钮、彩色圆点。
跳地图与导出报告进了那条轻带。

**用量条换色这一条是顶着说明改的**：说明 §4 要环用蓝渐变，第一代我给线性用量条配的是
绿黄红三档（`--usage-*`）。这一轮把三档**从条上撤下来，只留在那个百分比数字上**
（≥90% 才点亮 `--usage-high`）。代价写进 `global.css` 的 token 注释：
一眼扫过去的色彩冲击弱了，得看数字才知道盘有多满。

## 4. 玻璃（§10）

`glass/tokens.css` 的填充档**按"身后是什么"重分成两档**，而不是统一调薄：

- `--glass-tint-page: .055` —— 页面玻璃换成一层白纱 + `--glass-sheen`（上亮下暗那道，就是"非均匀透明度"）。
- `--glass-fill-float: .88` / `--glass-fill-menu: .94` —— 浮在地图上的那两层**没跟着降**。
  V0.8 为这对数值量过对比度（次级文字从约 2.7:1 掉到约 2.1:1），
  把"卡片要薄"推广到"菜单也要薄"会直接牺牲地图上浮层的可读性。
  ⚠️ 那两个具体数字仍是旧灰底下量的、已作废，只剩"菜单比卡片实"这个结论站着。
- 圆角 20/16/12 → **16/12/10**。
- `.dc-hud` 从"玻璃卡 + blur"降成一条轻带（它是过程读数，第一代却给了它全屏最重的 16 px 粗数字）。

**"折射"没有做**：CSS 只到边缘高光 + 内应力阴影那一层，真折射要 WebGL，V0.8 裁定 3 已否。
注释里也没把它写成折射。

`.dc-card` 的 `background-color` 与 `background-image` **故意分两行写**：
合成一条渐变的话，computed `background-color` 会退回 `rgba(0,0,0,0)`，
而 §23 呈现层判据读的就是它 —— 那会对一块画得好好的玻璃报红。

## 5. 新增的那一格设置（§3 的「设置」）

说明把「设置」列进导航，而本项目的老规矩是"没有真逻辑在读的控件不许画"
（第一代 U11 因此拒过它一次）。这一轮接受，**代价是先把它接上**：

- `shared/settings.ts` —— `AppSettings { dupMinSizeMb }`，默认值与 `DEFAULT_DUP_MIN_SIZE_BYTES` 派生自同一处；
  `core/dup/detect.ts` 与 `electron/services/dup-service.ts` **原本各写了一份 `4 * 1024 * 1024`**，现在都指向这一处。
- `electron/services/settings-service.ts` —— 落 `userData/settings.json`，读永不抛（缺文件给默认、坏文件给默认**并点名**），
  写走临时文件 + `renameSync`，失败**抛错**，所以界面不许说"已存好"。
- 一格控件：重复文件最小尺寸。改完立刻存、按服务端回执重画、请求带序号丢旧回执。
  能选 1–1024 MB，选项清单 = 预设 ∪ 文件里当前值（手改过的 5 不会显示成别的数）。
- 「关于」只有版本号一条。规则条数**渲染端取不到**（`BUILTIN_RULES` 在主进程、没有通道报它），
  所以那一行没画 —— 没有真数据就没有那一行。

`--shot` 新增一步：它**按文字点侧栏**进设置（不是 `__dc.view`），再比
DOM 里 `<select>` 的值 vs 主进程 `getSettings()` 的回执。真值 `{"ipc":4,"dom":"4","title":"设置"}`。
这一步存在的理由：组件没被任何路由引用时会被 tree-shake 掉，`npm run build` 成功
**不构成"用户走得到那一页"的证据**。

## 6. 判据变更与变异证明

§23 首页那一跑重写了一遍（第一代那五块卡的类名已经不存在），现在 10 条，编号与分工写在代码注释里。
本轮新加的四条各证了一次能红：

| 判据 | 装的变异 | 结果 |
|---|---|---|
| ⑨ 面板不许蓝主导 | `.dc-card` 底色装回 `rgba(12,44,97,.86)` | `FAIL: 主面板底色蓝主导度 85（B−R），超过 12` |
| ⑧ 导航标签必须在 DOM | `<span className="dc-nav-label">{n.label}</span>` → 空 span | `FAIL: 第 0、1、2、3、4、5、6 个导航按钮 textContent 是空的` |
| ③ 列轨道数 = 2 | （随 `.dc-home-grid` 一起改，跑绿即成立） | `tracks: 2` |
| ⑩ 按钮必须蓝主导 | 未单独装（它与 ⑨ 是一对，⑨ 红时 ⑩ 仍绿，说明两条互不遮蔽） | `ctaBlue: 168` |

**⑧ 那条的变异顺带证掉了注释里的一句话**：标签一空，**另外 24 步**（step 36 那一族
「侧栏「垃圾清理」点不动」「点了侧栏却没换到记录页」）同时红 ——
"文字挪出 DOM 会让那四步全红"不是修辞，是量出来的。
那一跑总 `failures=26`；两条文件还原后重跑 `failures=0`。

呈现层的 alpha 阈值这一轮从 `> 0.05` 降到 `> 0.02`：
第二轮的真玻璃本来就是一层白纱（`.055`），卡在 .05 等于让判据对**合法值**报红。
判据要抓的是"零"，不是"薄"。
