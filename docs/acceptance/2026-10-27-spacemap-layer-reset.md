# 2026-10-27 晚 空间地图：返回上一级后蓝框落在别处

**一句话结论**：人类伙伴截图报「右键选中一个方块 → 返回上一级 → 蓝框还在，但框住的是这一层
**别的东西**」。根因不是"忘了清"，而是 `active` 里存的是一个 **`Tile` 对象**，
它带着 `x/y/w/h` 这一套**上一层的布局坐标**，高亮层照样拿它去 `project()` 画框 ——
于是框画进了新一层的坐标系。修法：`[nav.path]` 那个 effect 里连同选中与统计一起清掉。

---

## 1. 现象

人类伙伴给的截图：站在 `C:\Users` 这一层，蓝框却落在 AppData 那一格的位置上。

**为什么不是"框没跟着刷新"**：框的位置在这一层里是**有意义**的（它确实对齐着某个格子），
只是对齐到了错的那个 —— 那比"框停在原地不动"更难读，因为它看起来像"我选中了 AppData"。

---

## 2. 根因

```
active: Tile | null        // 存的是 Tile，不是 id
TreemapCanvas 高亮层：project(t, view)  // 拿 t 的 x/y/w/h 直接画
```

`Tile` 是**布局产物**（`toTiles` 按大小降序布格的结果），不是身份。换一层就是换一套布局，
同一个目录在新层里可能根本不存在，即便存在，坐标也是另一套。

所以"换层清掉 active"不是保守做法，是**唯一能保证框与格子对得上的做法**。

### 2.1 统计为什么一起清

`active` 与面板上的统计是**同一个动作**拉的（见 `pickTile` 的注释）。
只清一半的表现是"面板上没有名字、但有统计数字"—— 那是另一个缺陷的形状。

### 2.2 为什么三件事必须在同一个 effect 里

`setPinned(false)` 本来就在那儿。新增的 `setActive(null)` / `nav.clearStats()` 若散到别处，
就会出现"某一条路径走不到"—— 而这三件事本来就是同一个动作的三个面。

---

## 3. 判据（两半，第二半比较弱，如实登记）

本仓**没有 React 挂载设施**（渲染端一律测抽出来的纯判定），所以这一条只能分两半钉：

| 半 | 文件 | 条数 | 钉住什么 | 挡不住什么 |
| --- | --- | --- | --- | --- |
| ① 根因 | `treemap-view.test.ts` | +1 | 拿上一层的 `Tile` 在新一层里画框，**落点必然与那一层的格子错开** | 抓不住"有人把 `setActive(null)` 删了" |
| ② 行为 | `spacemap-layer-reset.test.ts` | 4（新文件） | 那个 effect 体里三件事都在（`setActive(null)` / `nav.clearStats()` / `setPinned(false)`） | 挡不住"在别处又塞一份 `active`" |

**实测过的无效判据**：删掉 `setActive(null)` 之后，`treemap-view.test.ts` 那一整份（14 条）
**全绿** —— 所以①单独存在时是一条**证明不了回归**的判据。
（这条实测记在 `spacemap-layer-reset.test.ts` 文件头，是那半"比较弱"的由来。）
要升级成真行为用例，得先给仓里装一套 mount 设施，那是另一批的事；
在那之前不许把这条说成"已被行为覆盖"。

### 3.1 取 effect 体那个坑

第一版正则写成 `/useEffect\(\(\) => \{([\s\S]*?)\}, \[nav\.path\]\)/`，
它会从文件里**第一个** `useEffect(() => {` 起匹配 —— 而 `SpaceMap.tsx` 前面还有别的 effect，
于是捕获体是**别人的整个函数体**。那里面恰好有 `setActive(null)`，
所以"删掉换层那行"这个变异**测不出来**（实测：变异后 4 条全绿）。

正确做法：先定位 `}, [nav.path])`（全文只有一处），再从它**往前**找最近的
`useEffect(() => {`。另加一条自检：取到的体长度必须 < 400 字符，异常长就说明吞了别的 effect。

### 3.2 夹具那个坑（`treemap-view` 那半）

两层的选中格都从 `(0,0)` 起 ⇒ 坐标恰好相同 ⇒ 判据成了恒真。
而想靠"排在后面"避开原点也没用：`toTiles` 是**按大小降序**布格的，最大的那格永远在 `(0,0)`。
夹具改成「上一层选中的是第二大（`x > 0`），这一层最大格占满前半屏」，并先断言两者 `x` 不同 ——
前提不成立时判据自己会红。

## 5. 未做 / 已知代价（如实登记）

1. **没有真机截图**。这一格的证据是"根因判据 + 源码闸"，**不是**"点一遍看框在哪"。
   人类伙伴报的那张截图是**缺陷**的样子，修好之后没有对应的那一张。
2. **这一条挡不住"在别处又塞一份 `active`"**，也挡不住"把清空挪进一个走不到的路径"。
   真行为覆盖要先有 mount 设施。
3. **`SpaceMap.tsx` 的注释里写着「同层重画（依赖没变）不会走到这里」** —— 这句是对的，
   但它依赖 `nav.path` 的引用只在换层时变。若将来有人在同层重画时换掉那个引用，
   用户会看到"扫描轮询期间选中被清掉"。今天没有这条路径，登记在此。
