## 「没量过」必须念得出来（半棒 2a）

`reclaimIsUpperBound` / `hardlinkCheck` 以前只算不上界面。现在：量过的组念**准数、不带任何 hedge**（给量过的数挂上限同样是说谎）；没量过的念 `≤ X（未能确认硬链接）` 或 `≤ X（本轮未核查硬链接）` —— 两种"没量过"理由不同，话也不许混成一句。三条方向性的判断值得单独记：

1. **两个标记只到一个时走"上限"那一支** —— 少说是错的，多说"没量过"才是安全方向。
2. **一组纯硬链接按簇计价就是 0，`preview.ts` 于是以 `nothing-to-confirm` 拒绝发通行证 —— 这是设计不是缺陷**；缺陷是界面上只剩一个灰按钮。现在把理由写在行里（"每条待删路径占的那份字节都还有别的名字攥着"）。但**上限口径下的 0 不许套用这句** —— 那是读数的偶然，不是量出来的"省不下"。
3. **合计掺进任何一组上限，整个合计就只能念成 `≤`**，并点名有几组是上限（`dup-render.test.tsx:173`）。混合精度求和再标成准数，是这一版最容易犯的错。

## 本轮顺带查出的一条更大事实：§19 的「实际释放」也是 inode 盲的

`actualFreedBytes` 与 `predictedFreedBytes` **都是逐路径表观大小之和**（`measureRoot` 复用 Scanner 按路径累加，结构上没有 inode 概念）。所以有硬链接参与时两边同口径、`deltaBytes` 精确等于 0，而盘上一个字节都没少 —— 靶场读数：§19 三个数全是 67,108,864，卷真实可用空间变化只有 33,456,128。

**两个错口径互相印证，比单独一个错更危险**：`deltaBytes=0` 看起来是"验证通过"。已改口三处文案（`executor.ts` 的 `note`、`Cleanup.tsx` 的「（完全吻合）」、`executor.ts:22` 那份"会造成差的原因"清单 —— 它以前只列会差的，漏了会**假性相等**的那一种）。**数字本身没动，`verification` 的计算与六道闸一字未改**：要改的是它说什么，不是它算什么。

## 2026-10-07 更正：5d 独立评审推翻本文一条断言，已修

5c/5d 的独立评审（`Needs fixes`，无 Critical）翻出一条我写在 §2.7 那张表里的假话：**「`findings.ts` 的计价改用逐路径值，预览总额不再虚报」在"用户摘出一份"之后不成立** —— 而 5d 恰恰就是"用户摘出一份"那一棒。

机制：`detect.ts` 的价表是按**全量待删**发的（一个簇只有一条拿到 `size`，同簇其余 0）。`findings.ts` 原来把这些旧价按幸存清单加一遍，于是**当用户摘掉的是那一条 0 价的兄弟**时，留下的带价那条仍报 `size`，而真相是它的名字还被刚摘出去那一条攥着 —— 删完一个字节都不省。**方向是虚报，正是 §2.7 那一类，也正是半棒 1 被创建出来要灭掉的东西**，被 5d 重新引入。

最坏的是它**没有任何一道闸会红**：两侧账目内部自洽（`totalBytes == Σ allPaths.size`），`recordExecution` 的自检与 `nothing-to-confirm` 都在同一口径里，所以"内部一致"又一次冒充了"与事实一致"（同一天的第二次，见 [[feedback-corroborating-measures-share-blind-spots]]）。

修法与验证：簇身份（`clusterOfPath` / `clusterWhole`）从 `detect.ts` 一起发出，`findings.ts` 改成**按簇重算** —— 一个簇省下一份字节，当且仅当"这一组看到了它的全部名字"且"这些名字现在全在幸存清单里"。先写的失败用例复现出 `报 8,388,608 / 真值 0`，修后 `915 passed / 57 files`、typecheck 0、build 0、`--shot` 整套 `shot-failures.txt = 0`。用例里同时钉了反向半边（摘掉与 `keepPath` 同簇那条不影响另一簇）与"什么都不摘时与 `reclaimableBytes` 逐字相等"。

**仍然没修的那一半（如实记着，别当已闭合）**：页脚/行内的「按剩下的几份计」是客户端自己加旧价表的（`Duplicates.tsx` 的 `dupSurvivingBytes`），所以窄场景下界面仍可能比服务端多说一份。已在那个函数上写明不一致与修法（规则要抽进 `shared/`，因为渲染端没有引 `core/dup` 的先例、而 `core/dup` 有静态纯度闸）。**后果限于把"能省"说多，不会多删任何东西** —— 工作单由服务端算，那一侧已经对了。

评审另留三条未修，都已立任务：I-2（`dupSurvivingBytes === 0` 被当成"全部摘出"，而幸存但 0 价时它照样会被删 —— 判据应是幸存**条数**）、I-3（§2.3 那行进度字只有源码字符串判据，把 effect 改成"收了事件不用载荷"四条全绿而屏幕一个数字都不动；`5f14ed6` 之后 `report` 已是 props，当年为 `DupGroupsTable` 用的渲染判据办法现在可用）、I-4（一轮检测的状态现在有两个主人：`report` 住 App，`busy`/`progress`/取消按钮住页面 → 走"开跑 → 去清理页 → 回来"会丢掉取消能力并照常显示旧结果）。
