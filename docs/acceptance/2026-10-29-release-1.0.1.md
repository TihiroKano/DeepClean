## 1. 五条分别改在哪

### ① 首页切盘药丸点不动

**症状**（人类伙伴）：「图一这个 windows 无法点击」。

**根因**：`<label class="dc-drive-pick">` 包着 `<select>`。药丸的可视面积大半是 label 的
padding，而 Chromium 对"已经包在 label 里的 select"再走一次 label 激活时，会把开/关
当成两次切换 —— 表现是点 padding 完全没反应、点下拉文字偶尔能开。

**改法**：换成 `<button>` + 自绘菜单（`Home.tsx` 的 `DrivePicker`）。
`<button>` 天生可聚焦、`Enter`/`Space` 可用、点哪里都算它自己的。
菜单自己管外点关闭与 Esc，菜单项是真正的 `<button>`（Tab 能到、读屏天然可读）。

**代价登记**：多了一张自绘菜单（定位 / 外点 / Esc 三件事要自己管）。换来的是键盘可达 ——
原来的 `<select>` 那一路在 label 里坏掉之后就没有第二条路了。

### ② 换盘后首页仍然显示 Windows 的占用

**症状**（人类伙伴）：「当清理位置选择为其他盘时，主页面数据应该也跟着改变，而不是依旧
显示 Windows 占用」。

**根因不是布局，是两处各自算了一遍"扫的是谁"**：
- 环 / 已使用 / 总容量 / 剩余 读的是 `drives.find(d => d.root === root)`，
  而 `root` 是**盘符下拉那一格**（"下一次扫哪"）；
- 文件数 / 用时 / 可清理 读的是**快照**（"刚才真扫了哪"）。

于是扫了 D 盘之后，左半边还画着 C 盘。两处各自成立、合起来矛盾。

**改法**：`useScan` 暴露 `scannedRoot = snapshot?.root ?? null`（主进程在快照里报的那个根），
首页所有"这块盘"的读数一律读它。下拉那两格回归本分：**下一次**扫什么。

两处回退有意：
- 没扫过 → 显示占位符，不画一块没采过的盘；
- 扫的是自定义目录（`D:\Games`）时按**盘符前缀**找到所在那块盘 ——
  "已使用 / 总容量"本来就只能是整盘口径。找不到（网络路径、已拔的盘）就空着，不编。

### ③ 并行扫描倍数（设置 → 性能，滑块）

人类伙伴原话：「清理过程的并行清理倍数放在设置以滑块方式选择，默认为推荐值，
推荐值采用当前设备支持的最保守倍数，以确保用户拉满倍率导致崩溃的情况发生」。

落成三件事：

| 要求 | 落点 |
| --- | --- |
| 滑块 | `Settings.tsx` 的 `PerformanceCard`，`type="range"`，1–16 |
| 默认推荐值 | `SCAN_WORKERS_AUTO = 0` 这个哨兵档，界面显示「推荐」 |
| 拉满不崩 | **不在界面这一侧**，在扫描内核的 `clamp_workers` |

**上界为什么分三层**：

- 滑块 `max = 16`（`MAX_SCAN_WORKERS`）—— 界面能拉到的最大倍率；
- 服务端清洗 `MAX_SCAN_WORKERS_HARD = 64` —— 收得下"手改文件写了 40"；
- **真正的安全上界在 `clamp_workers`**：`1..=逻辑核数 ×2`。

第三条不是装饰：`settings.json` 是外面能手改的文件，界面挡不住它。
`usize::MAX` 条线程会当场把进程打死 —— 而"拉满倍率导致崩溃"正是这一格要防的事。
下界是 1 而不是 0：0 条 worker 会让 `join` 立刻返回一棵**空树**，界面上表现为
"这块盘什么都没占"，比崩溃更难查。

**默认值与 1.0.0 逐字相同**：`scanWorkers = 0` → `None` → `available_parallelism()`，
就是改之前那一行。

### ④ 安装器语言改成中文

```diff
  "nsis": {
    "installMode": "perMachine",
+   "languages": ["SimpChinese", "English"],
+   "displayLanguageSelector": false
  }
```

**判据落在哪**：不是读配置文件，是读 **makensis 实际吃进去的那份 `installer.nsi`** ——
第 465–466 行是

```
!insertmacro MUI_LANGUAGE "SimpChinese"
!insertmacro MUI_LANGUAGE "English"
```

`SimpChinese` 在前 = 中文系统上默认中文。`displayLanguageSelector: false` 表示
不弹语言选择框（用户没要求那个）。

### ⑤ 界面语言：五种，切换即时生效

`设置 → 界面语言`：简体中文 / 繁體中文 / English / 日本語 / 한국어。

**实现的三条要点**：

1. **键就是中文原文**，查不到就回原文（`i18n/dict.ts`）。
   漏译的失败形态是"那句话显示成中文"，不是"界面上冒出 `home.startScan` 这种字样"。
   前者是欠账，后者是缺陷 —— 而欠账可以一条条补。
2. **`LocaleContext` 挂在 `App` 外层**，`useT()` 往下取。换语言 = 换一次 context 值，
   React 自己重渲染，不需要任何组件知道这件事。
3. **`<html lang>` 跟着设置走**。`lang="zh-CN"` 下日语汉字会走简体字形
   （「直」「骨」那几笔不一样），那是"看着像没译对"的一半来源。
   同时写 `data-dc-locale` 给 CSS 用（日语放松行高、韩语 `keep-all`、英语 `hyphens`）。

**默认简体，与 1.0.0 的界面逐字相同** —— 这条有判据钉着：
`tests/unit/i18n-locale.test.ts` ③ 那条遍历 `ZH_CN` 的每一条，要求 `值 === 键`。

## 4. 没做的（如实登记）

1. **装机验收没跑**（`m6-install-verify.ps1` 那六相）。要 UAC（`installMode=perMachine`），
   且会改这台机器的 HKLM / Program Files / 开始菜单 —— 那一步要单独点头。
   ⇒「装进包里的那份 exe 带 requireAdministrator」这句仍然只有 `target\release` 那份的证据。
2. **安装包没签名**（`Get-AuthenticodeSignature` = `NotSigned`）。既有状态，本次没变，
   但分发给外部用户时会直接影响信任。
3. **界面语言只验到"渲染出来对"，没验"真窗口上切一次"**。
   判据覆盖：词典键集完整（缺 0）、简体逐字回原文、占位符保留、闭集清洗。
   **没验的**：真点一次下拉、真看整窗重渲染。那要开窗口截图。
4. **第 ② 条修复只验到"读的是快照那个根"，没验"真扫一块非 C 盘之后首页跟着变"**。
   要验得真跑一次 D 盘扫描 —— 那会读真实磁盘。
5. **`Cargo.lock` 里那 7 个 crate 的版本号**由 cargo 自动同步（下次任意一次
   `cargo build` 会写）。`git status` 里它没被列为改动，是因为这一轮最后一次编译
   已经把它写好了 —— 提交时它会一起进去。
6. **`1.0.0` 那份旧安装包仍在 `bundle\nsis\`**。要删要另说（1.0.0 验收那次删过，
   这次没动）。

## 5. 这一轮踩到的两个坑（留给下一个人）

### 坑一：并行改同一个文件

这一轮同时开了 4 个子代理翻译词典、主会话改界面。结果：
- 四份词典被多方并发追加，**互相产生过 21 个重复键**（JS 对象会把重复键静默吞掉，
  表现为"某一条译文莫名变成了后写入那份"）；
- `Cleanup.tsx` 被主会话与子代理同时改，子代理报过冲突预警。

**判据**：重复键只能用"源码行级数一遍 + 运行时 `Object.keys` 数一遍，两个数相等"来查
（只查其中一边会被静默去重骗过去）。最后实测 `377 == 377`，四个文件都是。

### 坑二：源码闸与 i18n 天然冲突

`cleanup-item-detail.test.tsx:113` 断言 `aria-label="关闭详情"` 这个**字面量形状**。
迁成 `aria-label={t('关闭详情')}` 之后它红了。

**处置**：判据跟着改，改成两种形态都认
（`/aria-label=(?:"关闭详情"|\{t\('关闭详情'\)\})/`）。
理由是那条判据问的是"那个 × 按钮有没有一个能被读屏念出来的名字"——
名字的来源从字面量换成词典不改变这个问题的答案。

同一处还有 `cleanup-layout-contract.test.ts` ④：它原来断言源码里能搜到「清理预览」，
现在那几个字在 `zh-CN.ts` 里。改成**真渲染**（拿简体词典跑 `t()`），
守的仍然是"e2e 还能不能按名字找到这块地标"。
