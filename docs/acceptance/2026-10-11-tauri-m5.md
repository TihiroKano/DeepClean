## 2. 两条口径决定（都写在 `dupes.rs` 文件头，这里给理由）

### 2.1 检测跑在**快照**上，而不是抱着树的锁

一轮检测在十万级文件上是几十秒到几分钟，而 `TreeIndex` 住在 `Session::state` 那把 `Mutex` 里 ——
抱着它跑会把 `dc_snapshot` / `dc_children` 全堵住，症状是"一点检测整个地图就死"（那边是 400 ms 轮询）。
所以锁里只做一次遍历取快照，出锁再 hash。

快照的取数**唯一**走 `TreeDupSource::children_of`（**计价口径**），不在壳里重写一遍目录展开 ——
这是 M2-A 那条红线的延伸：收窄漏进取数面 ⇒ 第 N+1 个之后的文件从重复检测里静默消失，
而重复检测的产物是一份删除建议。判据 `the_snapshot_agrees_with_the_tree_source_dir_by_dir`
逐目录比两边一字不差（变异 MU1 证明它真会红）。

### 2.2 禁止根 / 只上报根**传空**，与 TS 行为基线一致

`core/dup/**` 从来不给这两份清单（只有规则引擎给）。所以 Rust 侧也传空。
这是一个**两侧共同的既有缺口**：重复页会把禁止根之下的重复组列出来、并把它们的字节算进可回收合计。
删是删不掉的（§16 那道闸在预览/执行那一层照样拒），所以它是界面噪声与过度声称，不是安全洞。
**要修必须 TS + Rust 一起修** —— 与那条 rank-6 死分支同一处置纪律，登记待裁定，不在这里单方面改行为基准。

## 4. 真机（`scripts/m5-dupes-e2e.ps1`，exit=0，肉眼看过图）

自建夹具（三份同内容 + 一份只差一个字节，各 5 MiB），`DC_AUTOSCAN` 扫它，进重复文件页点
「开始查找重复文件」，然后**拿 PowerShell 自己算的 sha256 当独立口径**去比界面：

| 坐标 | oracle（`Get-FileHash`） | 界面上渲染出来的 |
| --- | --- | --- |
| 候选数 | 4 个文件 ≥ 4 MiB | 「候选 **4** 个（≥ 4.0 MB）」 |
| 同大小成组 | 1 个尺寸桶 | 「同大小成组 **1** 组」 |
| 确认组数 | 1 组（3 份同内容） | 「确认 **1** 组」 |
| 可释放 | (3−1) × 5,242,880 = 10,485,760 | 「可释放 **10.0 MB**」，两份待删各「省 5.0 MB」 |
| 组成员 | a.bin / b.bin / sub/d1.bin | 三条逐一点名；**c.bin 不在**（只差一字节） |
| 全量性 | 跑完没截断没取消 | 页面上没有「报告不是全量」那一句 |

图：`assets/m5-dupes-real.png`。保留位是 `a.bin`，页面同时念出了定序规则
（位置优先级 → 修改时间早者优先 → 路径字典序），这一条与内核的对账同源。

### 4.1 这一相里撞到的三个环境事实（都写进了脚本注释）

1. **`DC_AUTOSCAN` 扫完会自己跳到空间地图**，所以"扫完了"的坐标是**面包屑里出现了这棵根**，
   不是首页那颗「查看扫描结果」。我最初抄的是 `scripts/m3c-e2e-screenshot.ps1` 里的那颗按钮 ——
   而那个脚本一张图都没产出过，它的选择器一个都没被证明过。**抄一份没跑过的脚本里的选择器 = 没抄证据。**
2. **按 PID `FindFirst` 会撞上同进程的隐形窗口**（实测该进程有两个顶层窗口：
   `Tauri Window` 与一个 6×6 的 `Tao Thread Event Target`），命中后者时每一次"找不到元素"
   都是查错了地方。两份脚本现在都按类名挑。
3. **UIA 会把一句带插值的中文拆成多个文本节点**（抓到的"那一句"只有 `）→ 同大小成组 `），
   所以断言对象改成**按树序拼起来的一整块文本**。

### 4.2 界面上那句承诺，这一版还兑现不了

页面底部写着「勾选只是把组 id 交给 §17 的确认链」，而 Tauri 侧 `previewCleanup` 的 `dupGroupIds`
**仍抛 `E_NOT_IMPLEMENTED`** —— 也就是点「去清理页确认」这条路今天走不通。
这一格没有肉眼验过（不在本轮范围），它连同"翻译层没搬"一起记在 §6.1。

## 5. 顺带修掉的一处自身缺陷

`commands.rs` 里那条注册闸（`every_command_defined_here_is_registered_in_the_shell`）
原先只匹配 `pub fn dc_`，**匹配不到 `pub async fn`** —— 也就是说异步命令可以写完不注册而闸不红。
写 `dc_dupes_run` 时正好撞上这个洞（它是本仓第一条异步命令），已改成匹配 `fn dc_`。
这条闸的存在理由本来就是防"命令写好了没登记"（M4 那个缺漏的形状），结果它自己对最常见的一种
漏法免疫 —— 判据比它要防的东西窄，是这一仓反复点名的错。
