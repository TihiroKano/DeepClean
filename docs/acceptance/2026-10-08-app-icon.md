## 2. 图标资产：源图不是透明可用的

源图是一张带 alpha 通道的 PNG（IHDR color type=6）。**带通道 ≠ 背景透明**，实测两件事：

- 透明是真透明：463,685 个像素 alpha=0，四角全透。
- 但图身**几乎没有一个像素是全不透明**：alpha>250 的 1,088,239 个像素里 99.8% 落在 252–253，alpha==255 只有 2,245 个 —— 等于整张图标被做成约 1% 半透明。

处理与结果：

| 项 | 处理前 | 处理后 |
|---|---|---|
| 图身 alpha | 252–253（99.8% 非满值） | 归一到 255，涉及 1,090,538 个像素 |
| 边缘杂点（alpha 3–9 的纯蓝/纯青） | 10,533 | 0（alpha<24 一律置透） |
| 半透明 AA 环 | — | 5,601 个像素，保留 |
| 轮廓尺寸 | 1077×1104 | 补成 1104×1104 正方形（左右各 13px 透明） |

白边残留判据：边界 3,875 个像素里「不透明且 R/G/B 全 >205 且色度 ≤24」的中性白 **0 个**，最亮的是 RGB(33,99,244)。这版源图的抗锯齿不是拿白底混的，所以不需要像上一版那样做白底 matte 反解。

## 3. 三处生效层，各自的判据

### ① 窗口标题栏 —— 过
`WM_GETICON` 的 `ICON_SMALL` 与 `ICON_BIG` 都返回真实 HICON（同一句柄 `102238803`）；DPI-aware 截真窗口标题栏，图标已是这版蓝底标而非 Electron 默认原子标。

### ② 任务栏按钮 —— 过（但取证的坑值得记）
任务栏处于**自动隐藏**状态：`Shell_TrayWnd` 矩形是 `[0,1438,2160,1510]`，而屏幕只有 1440 高 —— 整条停在屏幕外。所以「按屏幕最底 80px 截」永远截到的是别的窗口内容，连截两次都以为是自己裁错了位置。正确做法：把光标 `SetCursorPos` 到物理底边把它唤出，**再重读一次矩形**（停在屏幕外的矩形拿来截就是垃圾），拿到 `[0,1368,2160,1440]` 后截 2160×72。

结论证据是放大截图：x≈1362 处就是这版图标（蓝底 + 浅色 D + 扫帚 + 字标），紧邻 QQ 图标。

### ③ exe 内嵌图标 —— 过，两条独立判据
`npm run dist` 出 `dist/win-unpacked/DeepClean.exe`（246 MB）。

- **PE 资源逐字节**：`RT_GROUP_ICON` 4 条目 = 256/48/32/16、bpp=32，四帧的 md5（`36095946009B98E8` / `A5E518BFB9D2C057` / `846CE5C5DC85AC50` / `2755807D6E8A789B`）与 `build/icon.ico` 内的帧**完全一致 → 4/4**。对照组 `node_modules/electron/dist/electron.exe` **0/4**，且它那四帧长度 1320/5160/11560/18963、只有最大那一帧是 PNG 压缩。
- **Windows 自己的解析路径**：`SHGetFileInfo` + `DrawIconEx` 渲染出来，与 `build/icon.png` 缩到 32px 的均值色差 **0.3**；对照组 **68.4**。三张并排（参照 / 我们的 exe / electron.exe）肉眼也是「左中一致、右完全不同」。

## 4. 一条被判无分辨力、当场作废的判据

本来想用「模板在任务栏截图上滑动的最小平均色差」当量化证据。跑出来：

```
DeepClean icon  @32px  bestDelta=32.2   @40px 32.6   @48px 50.3
Electron 默认标  @32px  bestDelta=32.6   @40px 35.3   @48px 35.3
```

两边几乎同分 —— 深色任务栏上任何深色图标都能拿这个分，判据**没有分辨力**，不能据它下结论。处置：这条只用于给出候选坐标 (1362,22)，最终结论改由放大截图那一票判定；上面 §3③ 换成逐字节 + 有对照组的色差，才重新拿到分辨力（4/4 vs 0/4、0.3 vs 68.4）。

## 5. 环境事实（下次别再探一遍）

- **不要设 `ELECTRON_BUILDER_BINARIES_MIRROR` 指 npmmirror**：它的 `electron-builder-binaries` 路径 302 到 `cdn.npmmirror.com` 之后是 **404**（nsis、winCodeSign 都试过）。默认 GitHub 源实测三个二进制全 200：winCodeSign-2.6.0 5.6 MB、nsis-3.0.4.1 1.29 MB、nsis-resources-3.4.1 0.73 MB。
- electron-builder 与 rcedit / app-builder-bin 走 npmmirror 正常（registry 元数据 200）。
- 本机空闲内存 1.15–1.4 GB，`--dir` 打包吃得下；`nsis` 安装包 target 因此**故意没配**。
- 打出来的 asar 里混进了 `js-tokens` / `loose-envify` 等 react 传递依赖（electron-builder 无条件收生产依赖，`files` 白名单挡不住）。实测 main/preload 只 `require` electron 与 node 内建，React 已被 vite 打进 renderer bundle，所以这些是死重；总计 asar 6.5 MB，不值得为它加排除规则。

## 6. 未闭合（不写成已完）

1. **安装包没有**：`win.target` 只配了 `dir`。要分发还得加 nsis，届时会多下一个二进制并起 7z 解压。
2. **AUMID 那行是不是必需，没验**：任务栏图标显示正确是在**加了 AUMID 之后**测的，没做「去掉 AUMID 再截一次」的对照，所以只能说「带着它对」，不能说「必须有它才对」。
3. **小尺寸仍会糊**：32/16 下 `DeepClean` 字标不可读（§4 的放大截图里已经能看到字标糊成一条）。正经做法是另出一版无字标的图标，那是设计活，本版没动。
4. **exe 图标只在 `--dir` 产物上验过**：没装到别台机器、没验资源管理器图标缓存刷新后的样子。
