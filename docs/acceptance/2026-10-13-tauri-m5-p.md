### 2.3 对账抓出的第一个真缺陷：`crash-dumps` 白漏

第一版 `crash-dumps` 写的是 `paths = %LOCALAPPDATA%\CrashDumps` 直取，实测只有 1 root。
查 JSON：`%PROGRAMDATA%\Comms\BasicService\werdump` 里那 72 MiB 转储**既没有 finding 也没有任何排除记录**
—— 是"根本没去试"，不是"被别的规则认领走"（这两种长得一样，只有查排除记录才分得开）。

改成容器入口 + `leafDirs = CrashDumps / werdump / DumpFolder / Dumps` 之后，roots 从 1 变 **5**，
新捞到三个旧写法永远到不了的地方：

```
C:\ProgramData\NVIDIA Corporation\CrashDumps
C:\ProgramData\Razer\Chroma SDK\CrashDumps
C:\ProgramData\Razer\Synapse3\CrashDumps
```

**这是本轮"按构造机器无关"这个主张第一次拿到真机证据** —— 不是嘴上说的：一台机器上就躺着三个
不同厂商的 `CrashDumps`，写死任何一条路径都会漏掉另外两条。

### 2.4 对账抓出的第二个问题：Defender 病毒库被列为地盘（我此前定性说过头了，这里更正）

第一版对账里 `installer-artifacts` 的 30 个 root 里有
`C:\ProgramData\Microsoft\Windows Defender\Definition Updates\Updates`。

**更正**：我在 commit `0d4f9ce` 的信息里写它"把病毒库收走了"。复核对账数据后这是**夸大**的：
加了围栏 deny 之后 roots 从 30 变 29，而 `totalBytes` **两次一模一样**（3,804.05 MiB）
⇒ 那个目录在这台机器上贡献了 **0 文件 0 字节**，实际什么都不会删。
修仍然要做，但理由要说准：① "被列为清理地盘"本身就已经是错的定性；② 换台机器特征库可能就是
`.exe` 载荷，那时就是真删了。

修法是放进 `FENCE_MINIMUM_DENY_PATTERNS`（3→4）而**不是**只补那一条规则 —— 地板由
`validate_fence` 强制，任何容器入口规则漏了它整条拒；`a_fence_must_encompass_every_forbidden_root`
的 drop 清单同步加上第四条，"漏了会怎样"被测过而不是被相信。

修完的对账证据：`outside-fence` 排除记录 **4 条，四条容器规则各一条，全部点名
`C:\ProgramData\Microsoft\Windows Defender`** —— 围栏在真机上确实在咬，且是"根本不枚举 + 点名路径"那个形状。

### 2.5 golden 的两处归属写错了，按实测更正（字节没丢没重计）

`claimed` 表先声明者计账，新规则全在表尾 ⇒ 重叠归既有/靠前的那条：

1. `electron\Cache` 452.6 / `electron-builder\Cache` 73.6 / `NuGet\Cache` 都以 `Cache` 收尾，
   归第 16 条 `app-cache-data`，不归 `dev-tool-cache`。
2. `%PROGRAMDATA%\USOShared` 里 70 个 `*.etl` 归第 17 条 `app-rotated-logs`（`*.etl` 在它的名单里），
   `dev-tool-cache` 拿到的是 `claimed-by-other-rule`（JSON 里 70 条，逐条点名）。

所以 `dev-tool-cache` 实测只有 52.72 MiB（= `USOPrivate`）。**这不是双计缺陷，是归属**：
`ClaimedByOtherRule` 共 2,628 条，正是防双计那张表在大规模起作用。
但要说清代价：`dev-tool-cache` 的 description 承诺了"Electron 与 electron-builder 的下载缓存"，
而这几笔账挂在别的行上 —— 用户在界面上看到的归属会和文案不一致。**没为好看去重排表序**
（表序本身就是 `claimed` 判据，`builtin.rs` 有序 id 测试钉着）。

## 4. 未验证项与欠账（不许压缩成"已验证通用"）

1. **只有一台设备。** §2 证明本机没漏没误吃，合成树近失用例证明形状判据有边界，
   两者合起来**不等于**"在所有设备上有效"。形状名单人工维护，第一版必然漏（有的应用把缓存叫
   `scratch`）。漏的后果是**少删**，不是多删。
2. **`user-downloads-installers` 本机 0 命中** ⇒ 它只有合成树证明，没有真机证明。
3. **肉眼截图没跑。** 本仓已无截图通路（`--shot` 随 Electron 壳删，`package.json` 里没有
   `dev` / `tauri` / `shot`）。所以 🟠 告警面板的**排版**（长 description 溢出、叠字、
   flex 子项撑宽根）一个字没被眼睛看过。纯函数测的是"数对不对"，测不到"画出来是什么样"。
4. **端到端没跑**：真开窗口、勾一条 🟠、看见面板、按 high 拿到回执。
5. `dup:*` 伪项的 `description` 仍是空串 —— 若某条重复组被翻成 high，面板会画一行**没有解释文字**
   的条目。修法在模型侧补字段（并接受再一次 digest 换号），**不许**在 `Cleanup.tsx` 现编。
6. **M5-P2 未做**：`crates/appfacts`（注册表 / Appx / 进程 / 安装目录四路证据、
   `Absent := 有痕迹 ∧ 无本体`、`Unknown` 弃权）与 `orphan-app-data`。
   本机已确认的卸载残留 **1,592.6 MiB** 因此仍然没人管。它反转 `detectors.rs:19` 的注册表禁令，
   单独一份 spec + plan。
7. §7 变异清单第 7 条（从 `RULE_OPTIONAL_FIELDS` 删新字段演示静默失效）**没跑** ——
   T5a 的字段在 `PreviewItem` 上不在 `Rule` 上，那条变异够不着；要跑得等 M5-P2 的
   `requiresAbsentAppFact` 真的被用上。
8. `cargo test -p deepclean-app` 带一条**链接器**告警
   `.rsrc merge failure: multiple non-default manifests`（test 二进制特有，非本轮引入，
   本轮没查也没修）。M6 出包要求零告警，这一格是欠账。
