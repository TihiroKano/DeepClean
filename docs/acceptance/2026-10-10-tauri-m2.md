## 3. 本轮抓到的缺陷（**M2 最重要的产出**）

### 3.1 占用口径在压缩卷上少报 25%

- **现象**：`C:\Program Files` 上 Rust 报占用 **4.84 GB**，独立口径报 **6.46 GB** —— 差 **1.6 GB / 25%**。
- **定位**：逐文件对照，`C:\Program Files\Windows NT\Accessories\wordpad.exe`
  逻辑 2,932,736 B，Rust 报 `alloc=0`，而 `FileStandardInfo` 报 1,191,936 B。
- **根因**：**Compact OS / NTFS 压缩**的文件，**目录项里的 `FILE_ID_BOTH_DIR_INFO.AllocationSize` 是 0**。
  M1 的"一次遍历同取占用大小"因此对压缩文件完全失效。
- **为什么 M1 没抓住**：M1 的判据是「占用合计 **≤** 卷容量」。**少报时这条自动成立** ——
  M1 的验收在这条轴上只有上界、没有下界，和一个漏水的桶比"水没溢出来"。
  这是本项目点名的「互相印证的数共享同一个盲区」的又一例。
- **修法**：目录项报 0 而逻辑大小非 0 时，退化成一次**按路径**的 `GetCompressedFileSizeW`
  （比开句柄便宜；实测与 `FileStandardInfo` 同值）。正常文件一次额外调用都不多花。
- **修后**：六轴精确相等（见上表）。

### 3.2 独立口径自己也有一个坑（已修）

第一版 oracle 用 `Get-ChildItem -Recurse`，**它会跟着 junction 走** —— 而规格书第一条就是
「junction / 符号链接一律不进入」。上面那 26 个 reparse 点（Office App-V 的 vfs、NVIDIA 插件、
Nutstore bin、`Windows NT\附件`）让它多算了 **1.6 GB**。
**两边的偏差当时是"我只多 1.6G、你少 1.6G"叠在一起**，正好互相掩护：一个跟着 junction 多走，
一个压缩文件少报。修完 oracle（自己递归、遇 0x400 位跳过）才把两个问题分开看见。
oracle 已改为与 Rust 同口径。

### 3.3 界面口径标签与数据不符（已修）

界面全篇写着「表观大小」，而 Tauri 侧的 Rust 内核给的是**占用**（已去重、按簇计）——
**标签在撒谎**。修法不是把字面量改成"占用"（那会让 Electron 侧说错），而是**让标签从数据里读**：
新增 `ChildrenPayload.sizeBasis`（Rust 回 `'allocated'`，Electron 侧不带 ⇒ 缺省 `'apparent'`），
`Breadcrumb` / `DetailPanel` / `FileTable` / `TreemapCanvas` 四处标签读它。
图上因此从「表观 49.3 GB」变成「**占用 49.3 GB**」。

## 4. 两个由真机暴露的接线缺陷（已修）

1. **`E_NOT_IMPLEMENTED` 同步抛错会把 React 树整棵打挂。** 契约写的是 `Promise<T>`，而渲染端的钩子
   都是防御式的（`.catch` / try-catch）。**同步抛绕过 `.catch`**，地图页因此白屏，
   错误信息看起来像"previewCleanup 没实现"，其实是"失败形状和契约不一致"。
   改成 **rejected promise**（订阅类另算，见适配器注释）。
2. **前端不认识"后端起的扫描"。** `scanId` 只由 `useScan.start()` 写入，后端起的扫描（dev 自动扫描、
   将来多窗口）前端不认 ⇒ 「扫描完成后自动进空间地图」静默不发生。改为从 `ScanEvent` 里**采纳** `scanId`。

## 5. 未闭合 / 已知边界

1. **M2 只接了 10 个命令**：`dc_drives` / `dc_start` / `dc_cancel` / `dc_pause` / `dc_resume` /
   `dc_snapshot` / `dc_children` / `dc_dir_stats` / `dc_skipped` / `dc_dev_autoscan`。
   其余方法在适配器里**回 rejected promise**（`E_NOT_IMPLEMENTED`），于是
   **空间地图的「可清理」着色没有**（`previewCleanup` 属 §17，M3）。
2. **未做同一时刻的背靠背**：上面的对账是两次相邻运行，活盘会漂移（本次两侧分钟级内，未观测到漂移）。
3. **与 SpaceSniffer 的对比未做** —— 判据改用 `scripts/oracle-alloc.ps1`：它是**另一套 Win32 API**，
   比"另一个程序"更硬。规格书那句「与 SpaceSniffer 对比」按此收窄，理由记在这里。
4. **`C:\` 整盘的一级目录差异未逐项跑**（oracle 逐文件开句柄，整盘约 47 万文件，耗时以十分钟计）。
   拿 `C:\Program Files`（5.5 万文件、含压缩与 junction 两类难例）当样本，六轴零差。
5. `src-tauri/dist` 已改回**构建产物**（`npm run build:tauri` 产出），不再进版本控制；
   M0 那份手写静态快照退役。
