## 1. 为什么这条链要跑三轮、两档门槛

要判的不是"改没改成"，而是**哪一轮该用哪个值**。所以：

| 轮 | 开跑时设置页 | 跑的过程中做了什么 | 报告该写 |
| --- | --- | --- | --- |
| 1 | 4.0 MB（默认） | 什么都不做，只拿一份"有控件可点"的报告 | ≥ 4.0 MB |
| 2 | 跑起来后改成 **8.0 MB** | ① 途中点旧报告的复选框/「这份别删」② 途中回重复页读旧报告那句 | **仍 ≥ 4.0 MB**（它是改之前开的） |
| 3 | 8.0 MB | — | ≥ 8.0 MB，且候选数必须变 |

夹具刻意让两档门槛**给出不同的候选数**，否则"改了等于没改"看不出来：
`D:\dc-m5o-fixture` = 60 个 4 MiB（互相逐字节相同）+ 20 个 9 MiB（互相逐字节相同）
⇒ 独立口径算出 ≥4 MB 候选 80、≥8 MB 候选 20。脚本在起跑前就断言
"两档候选数不许相等"，相等就直接失败 —— 那是这一相**没有分辨力**的时刻，不能往下量。

三条独立坐标：① 候选数由 `Get-ChildItem` 按 `Length ≥ N MB` 自己数；
② 设置页那句「当前按 X 计」与服务端回执那句「已存好：N MB」**两种渲染必须同源**
（一个是 `formatBytes`、一个是整数，脚本换算后比对，不是各读各的都"看着对"）；
③ 跑完逐名点名 80 个文件 / 440,401,920 字节一字未改（全程零删除）。

## 2. 量到的三格（真机读数）

```
A  复选框 2 个，其中 enabled 的 0 个
A  「这份别删」/「放回待删」按钮 78 个（按类型+逐字名取的），enabled 的 0 个
B  门槛已改档 4.0 MB → 8.0 MB；回执 8 MB 与界面那句 8.0 MB 同源
B  途中回到重复页，报告那句仍是 4.0 MB（新值是 8.0 MB ⇒ 不许被改写）
   第 2 轮（改档之前开的）报告门槛 = 4.0 MB          ← 跑着的那一轮不被追改
C  第 3 轮报告门槛 = 8.0 MB、候选 20 个              ← 与独立口径 20 逐字相等
   还原：按 1 次 UP 回到 4.0 MB
```

页面那句「改完要重跑一次「重复文件」才按新值算」**第一次被肉眼看过一次，并且是真的**：
`assets/m5o-04-midrun-report-still-old.png` 同一屏里同时存在
「已读 63 / 候选 80（全文 hash 阶段）」+「取消」（这一轮在跑）与
「候选 80 个（≥ 4.0 MB）→ 同大小成组 2 组 …」（旧报告，门槛没被改写）。

## 3. 我自己先红的两条（判据的牙齿先咬到自己）

1. **假报了一条缺陷**：第一版统计「这份别删」用"名字里含这几个字"，量出
   `158 个，其中 80 个 enabled` —— 差点写成"检测途中窄化按钮点得动，是缺陷"。
   实际是**父容器 `<li>` 的聚合 Name 也含「这份别删」**，而容器永远 `IsEnabled=true`。
   改成按 `ControlType.Button` + 名字逐字取之后是 `78 个 / enabled 0 个`，
   与代码一致（`Duplicates.tsx:288` 的 `disabled={busy}`，`busy` 确实经 `DupGroupsTable` 传下来）。
   这与记忆里那条「`-like` 文字命中的常是旁边那个 Text」是同一件事，我又犯了一次。
2. **还原逻辑错**：选项列表是升序的，DOWN 只会往**大**的走；我按两次 DOWN 想"绕回 4.0 MB"，
   结果一路升到 32.0 MB。改成按 UP 循环直到读回起点值。

另外两处字面量坑（都是本仓记过、仍然会踩的）：正则里 `≥（）` 写成字面量 ⇒ 无 BOM UTF-8
被按 ANSI 解码后与 UIA 真字符**永不相等**（症状是"界面明明有这句，正则读不出"）；
`当前按 8.0 MB 计` 两侧的空格漏 `\s*` 同理。

## 4. 真修的一条：`.dc-link` 没有 `:disabled` 样式

截图里那 78 个**已经 disabled** 的「这份别删」和能点的链接长得一模一样 ——
还是亮蓝色、`cursor: pointer`、hover 还画下划线。UIA 的 `IsEnabled` 报得完全正确，
所以**任何按控件属性写的判据都量不到这一条**，只有肉眼看得见。

修在样式层（`src/renderer/styles/global.css`，照 `.dc-btn:disabled` 同一族）：

```css
.dc-link:disabled { opacity: 0.4; cursor: not-allowed; }
.dc-link:disabled:hover { text-decoration: none; }
```

修后重拍（`assets/m5o-02-midrun-controls-disabled.png`）：那批链接明显变淡。
改前那一张留在 `assets/m5o-before-fix-link-no-disabled-style.png`（它原本是那次红掉的运行
自己拍的 `m5o-FAIL.png`，改名保下来当 before 图）—— 两张对照就是这条判据的全部内容。
代价与边界：全仓 `.dc-link` 共用这一条，凡是 disabled 的链接都会变淡 ——
这是想要的方向（"看着不能点"就是真话），但它是**呈现层**的改动，
没有机器判据守着（CSS 几何在单测里量不出来，与 M5-M 窄窗那条同一个处境）。

## 7. 未闭合

1. `.dc-link:disabled` 这条没有任何机器判据（呈现层，单测量不出 CSS），只有截图。
2. §6 那条 987→994 的差未解释。
3. 这一棒量的是**重复检测**途中改输入；**扫描途中**改控件（改盘符 / 改扫描范围 / 途中排除目录）
   仍没量 —— 那要另一棵树与另一条链，M5-M ② 严格说只结了一半。
4. 检测一轮在这台机器上很慢（80 个候选、440 MB，debug 版 77–124 s/轮），
   所以这条链不适合进任何"每次都跑"的闸；它是验收脚本，不是判据。
