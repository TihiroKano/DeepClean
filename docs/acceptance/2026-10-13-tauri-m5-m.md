## 1. ④ 同刻背靠背对账 —— M1/M2 那笔欠账结清了

**欠账的原形**：Rust 内核与旧实现（`core/scan`，Electron 那套一直在跑的 TS 扫描器）
从没在**同一时刻**比过。两边各自都跟独立口径对过账（M1-T5、M2 六轴），但那是"两次相邻运行"，
而活盘在动 —— M5-J 现场又撞见一次：同一棵树相邻两遍差出 125,125 vs 120,640。
那种差既不能算口径差也不能算缺陷，只能算**没量成**。

**形状是 `Rust → TS → Rust` 三趟背靠背**（`scripts/m5m-same-instant-reconcile.mjs`）：

- 两次 Rust 必须逐字相等 ⇒ 不等就是这棵树在自己动，这一轮**判 VOID 没有资格**，
  而不是去解释差异。这是"漂移"与"差异"唯一的分界动作。
- 然后 Rust 与 TS 比三轴。TS 侧走 `scripts/bench.mjs`（旧实现的扫描器本体），
  Rust 侧走新加的 `perf::scan_only_the_three_numbers`（**只扫描、只报数**，秒级 ——
  不复用 M5-F 那条大 bench，因为它后面还接了 arena/规则/2 万组合成翻译，几十秒墙钟，
  窗口越宽越可能量到的是漂移）。

三棵树，三轴全等（每棵都先过了漂移闸）：

| 树 | files | dirs（Rust +1 = TS） | bytes_logical |
| --- | --- | --- | --- |
| `C:\Windows\System32\en-US` | 1,734 = 1,734 | 7+1 = 8 | 42,589,925 = 42,589,925 |
| `C:\Program Files\WindowsPowerShell\Modules` | 154 = 154 | 52+1 = 53 | 2,656,729 = 2,656,729 |
| `D:\deepclean-fixture\f100k`（8.98 万文件） | 89,801 = 89,801 | 57+1 = 58 | 1,032,439,052 = 1,032,439,052 |

### `dirs` 那一格差 1，是"根算不算"的约定，不是谁数错了

两侧各自都自洽，代码里能各读出来：

- Rust `counters.dirs` 只在"发现一个**子**目录"时 +1（`crates/scanner/src/scan.rs:275`），
  并且有 `debug_assert_eq!(counters.dirs, root.dir_count)`（同文件 216 行）兜着 ⇒ 根不算自己。
- TS `TreeStore` 在 `this.rootId = this.beginDir(rootPath)`（`core/scan/tree-store.ts:306`）
  那一刻就把根计进了 `c.dirs`（同文件 337 行 `this.c.dirs++`）⇒ 同一棵树恒多 1。

**为什么不"对齐"**：M1-T5 那一格是拿 PowerShell `Get-ChildItem -Recurse -Force -Directory`
（同样不含根）当独立口径验过的，Rust 与它相等；把 Rust 改成 +1 会同时弄坏那条对账和上面
那个 arena 不变量，换来的只是"两个 UI 的目录数一样"。所以驱动里**显式 `+1` 并留出处**
（`AXES` 里那条注释），而不是把它算成一致替谁背书。

### 路上烧掉的两个坑（都记进了项目记忆）

1. 第一版驱动从**仓库根**跑 cargo 并带 `--manifest-path` ⇒ 没吃到 `src-tauri/.cargo/config.toml`
   里的 crates-io 镜像 ⇒ 换源、整棵 tauri 依赖树重编，还撞出
   `only metadata stub found for rlib dependency core` 这种**看着像代码坏了**的错。
2. 驱动用 `spawnSync(..., { shell: true })` 传带空格的路径 ⇒ `--dir=C:\Program Files\...`
   在空格处被劈开 ⇒ TS 那一趟报 `files=0 status=failed`，驱动差点把"3 轴不等"当成结论。
   **对照组算出 0，先怀疑探针。** 三处 `shell: true` 全去掉之后同一棵树立刻三轴全等。

## 2. ③ 窄窗（<900px）—— 从没量过，一量就中

`scripts/m5m-narrow-window-e2e.ps1`：同一棵真树（靶场，只读）扫完之后，把窗口
`MoveWindow` 到 880 / 760 两档，四张表各拍一张。截图按 DWM 的真实帧边界裁
（UIA 的 `BoundingRectangle` 含投影边，拿它当裁剪框会把**别的窗口的字**拍进验收图 ——
M5-K 那次就是这么脏了两张图）。

**拍出来的缺陷（改前，`m5m-narrow-760w-journal.png` 的第一版）**：
`.dc-bar` 是不换行的 flex 行，日期框 + 两个 select + 两个按钮 + 右边那句「未筛选」
再叠上 152px 的窗口按钮让位区 ⇒ 整行**撑出视口**：页面底出现横向滚动条，
而「全部风险」被窗口右缘**切掉**。

修法两条，第二条是被拍出来才知道要的：

1. `.dc-bar { flex-wrap: wrap; row-gap: 6px }` —— 换行而不是缩字号
   （这一行里每个控件都已经小到不能再小，缩下去就点不准）。
2. **只加 `flex-wrap` 会把一个缺陷换成另一个更难看的**：flex 子项默认允许收缩，
   而中文能在字与字之间断行 ⇒ 「清除筛选」「刷新」「未筛选」被挤成**竖排单字**
   （第一版修完拍出来就是这样，与 4af6d36 那次修的"操作列竖排单字"同一症状）。
   补 `.dc-bar > * { white-space: nowrap }`，换行就只发生在**控件之间**。

改后的 `m5m-narrow-760w-journal.png`：标签都是完整横排，控件分行排好，右缘没有裁切。

**这条判据没有单测**：`renderToStaticMarkup` 没有布局引擎，CSS 几何在单测里量不出来，
所以它的证据只有截图。这一点写在这里，不让"CSS 改了 + 闸全绿"冒充"窄窗验过了"。

### 同一次拍照抓到的第二条（也修了）

同一张图底部：页脚那句里的日志路径 `C:\Users\…\com.deepclean.app\logs\deepclean.log`
是个**不可断行的长 token**，760 宽下它顶到窗口右缘被截，页面底的横向滚动条也还在。
成因与 `.dc-bar` 无关 —— 那是段落里一个长 URL 样 token 缺断行规则。
补 `.dc-fineprint code { overflow-wrap: anywhere }`（范围只限页脚里的 `code`：
表格那些路径列有自己的列宽与省略号判据 `ellClip` 量着，不去动它们）。

重拍后的 `m5m-narrow-760w-journal.png`：路径分成三行留在栏内、右缘不再被截，
横向滚动条消失，代价是这一页多了条**竖向**滚动条（文字变高了，本来就该滚）。

> 这一条一开始登记成"没修也没装成修了"。续作时把它做完了，改的是同一处判据面：
> 三条窄窗缺陷（顶栏溢出、竖排单字、长路径截断）现在都是**修完并重新拍过**的状态。

### 重跑这条脚本时踩到的一个操作坑

`m5m-narrow-window-e2e.ps1` 中途 `throw` 时**不会**走到收尾的 `Stop-Process`，
于是那个 DeepClean 实例留在桌面上；下一次运行 `Find-Window "DeepClean"` 会抓到
**上一轮的旧窗口**（它还停在别的页面上），表现成「路径输入框没出现」。
本轮第二次运行就是这么红的 —— 不是 CSS 坏了。脚本里那句 `throw` 之前该带一次清理，
留作后续加固；今天的处置是先 `Get-Process deepclean-app | Stop-Process` 再跑。

## 3. ① 与 ②：没做，理由与代价

- **① §12（地图加入清理列表的具体文件）+ §20（重复组）同时勾选**的去重，
  仍然只有单元级判据（`crates/cleaner/src/confirm.rs` 那批）。真机那一次要串起
  扫描 → 地图右键加入 → 重复检测 → 勾一组 → 清理页预览，是一条比 M5-B/M5-C 各自那条
  更长的 UIA 链；本轮上下文预算已尽，硬做会做成"跑了一半没截图"。
  代价：两条**各自验过**的通道在**同一份勾选里并存**时会不会双计，今天仍然只有代码级证据。

  > **① 已于同日结掉，而且量到了东西（2026-10-13 续作，M5-N）**：真机链跑通后当场红 ——
  > 同一个 5 MiB 文件被 §12 与 §20 各计一次，预览报 `10.0 MB / 2 个文件`、**一条拒绝都不留**，
  > 连确认回执都带着那个盘上兑现不了的数。上面那句"仍然只有代码级证据"当时是保守了：
  > 连"代码级证据"都只覆盖了同规则与双逐路径两种形状，跨通道的整项×逐路径从来没有用例。
  > 修与代价见 `docs/acceptance/2026-10-13-tauri-m5-n.md`。② 仍未量。
- **② 扫描/检测途中改控件**（改阈值、途中勾一组）：M5-F/M5-J 验过"途中点导航"与
  "途中轮询"，没验过"途中改输入"。代价同上 —— 途中改输入会不会让一次过期的检测报告
  被当成新的用，今天没量过。

  > **② 的检测那半边已于同日量实（M5-O，`docs/acceptance/2026-10-13-tauri-m5-o.md`）**：
  > 跑着的那一轮**不**被新门槛追改（报告仍写 ≥ 4.0 MB 而设置页已是 8.0 MB），
  > 下一轮才按新值且候选数从 80 变 20（与独立口径逐字相等），途中旧报告的复选框与
  > 「这份别删」全部 `enabled=0`。顺带用截图抓到一条 UIA 报不出来的：`.dc-link` 没有
  > `:disabled` 样式，置灰的链接和能点的长得一样。**扫描途中**改控件（换盘符/换范围）仍未量 —— ② 严格说结了一半。
