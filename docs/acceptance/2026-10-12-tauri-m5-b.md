## 2. 三条不可妥协的性质，各自怎么钉的

1. **被保留的那份永远不进清单** —— `findings.rs:224-236` 的收窄只作用于 `deletable_paths`；
   壳层 `a_stored_report_translates_only_the_group_it_holds` 与真机回执的工作单两头各钉一次。
2. **通道只能收窄不能新增** —— 「这份别删」是 filter；把 `keep_path` 或组外路径报上来只会被点名忽略
   （`keeper` / `unknown-path` 进 stderr），产出仍是原清单的子集。
3. **摘过之后重算价格**（V0.6 5d 评审 I-1 那一支）—— 对账夹具 ②（同 inode 簇摘掉 0 价兄弟后留下的必须归 0）
   与 ⑧（大小写不同同一路径）⑩（一次勾两组）是这次新写出来的分支，各由一条 golden case 钉住。

## 3. 新加的那道跨语言闸

`commands::registration_tests::every_argument_the_bridge_sends_is_a_declared_parameter`：
桥发出的每个键必须是该命令声明过的形参。**漂了的形状**是 JS 送 `dupGroupIds` 而 Rust 形参改名 ⇒
Tauri 当"没给"、`Option` 静默成 `None` ⇒ 重复项整个从预估里消失，而 vitest 与 `cargo test` 各自全绿
（一边测"桥发出了键"，一边测"函数收到了参数"，中间那段线没人量）。M4 那个"命令写好了没注册"是同洞的
另一种漏法，由上面那条注册闸钉；这一条钉"注册了但参数名对不上"。

它自己也是被红教出来的：第一版把「看到 `invoke` 就往后找引号」当解析器，注释里
`能 invoke 成功、跑起来才发现形状不对"没人拦` 那个 `"` 造出幽灵命令名，当场 panic；
另一版从引号自身起步找配对引号，切出反向区间又 panic。现在要求 `invoke[(<泛型>)]('dc_…'` 这个形状。

crate 侧 V1–V5 由子代理跑并回报（各红 ≥1 条、还原后源文件 `cmp` 一致）；壳层与桥由主会话第一方跑：

**M3 红 0 的处置**：计划 §3 让照抄 TS 的 `if (!items.some(...))`。装上后拿变异拆掉它，一条判据都不红 ——

这是「结构性不可达」那一类：**死闸比没有更坏**（下一个人会以为去重是必要的），所以删闸，

## 5. 真机（`scripts/m5-preview-e2e.ps1`，exit 0，肉眼看过三张图）

| 确认回执 | 1 项 / 2 个文件 / 10.0 MB | 「已确认 1 项 / 2 个文件 / 10.0 MB（指纹 6565075de885a5e3）。回执不含路径清单」；「开始清理」变亮但**没点** | `m5b-02-confirmed.png`、`m5b-03-receipt.png` |

计入预估的那一项是服务端从自己存的那份报告里翻译出来的。
