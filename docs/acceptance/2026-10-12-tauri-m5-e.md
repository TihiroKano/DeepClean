### 真机四相（每相钉一件会骗到界面的失败）

1. **预置出界的值 99999 → 界面念「当前按 1.0 GB 计」**。钉的是「夹住而不是偷偷换成默认值」：
   写成 4 的话，「我明明改了」与「改动根本没生效」在屏幕上同形。同时反证没回落默认（页面里
   没有 `4.0 MB` 那句）。
2. **真点开下拉、真点「32 MB」→ 界面按服务端回执念 `32.0 MB`，盘上那份就是 32**。钉的是
   「回整份而不是回 `ok:true`」：那一格跟着回执重画，不跟着点击的意图画（截图里那句
   「已存好：32 MB（依据是服务端回执，不是这次点击本身）」就是这件事）。
3. **杀掉再起一次 → 仍念 `32.0 MB`**。钉的是真落盘，不是内存里改爽了。
4. **预置一份坏 JSON → 界面念默认 `4.0 MB`，页面照常渲染**。钉的是「读的那一刻不抛」：
   文件坏了/不存在都是能跑的状态。点名走 `eprintln!` —— 这一侧还没有文件日志
   （记录页那句 `logPath: null` 就是登记），这是**已知的过渡形态**，不是"有日志"。

顺带钉住一条两侧同形：`Set-Content -Encoding utf8` 写出的 **BOM** 会让 `serde_json` 报
「不是合法 JSON」，而 Node 的 `JSON.parse` 同样炸 —— 所以带 BOM 的设置文件两侧都走默认值。
探针第一版就是被这个坑到的（预置 99999 却读到 4），换成无 BOM 写法后①相才真跑起来。

| 闸 | 结果 |
| --- | --- |
| `cargo test --workspace --no-fail-fast` | **exit 0 / 472 passed / 0 failed** |
| `npm test` / `npm run typecheck` | **1205 / 74**、node+web 均 exit 0 |
| 真机 `scripts/m5e-paths-e2e.ps1` | **exit 0**，两相（新开出的窗口标题逐字点名） |
| 变异电池 | P1–P5 五条，各红 1–2 条，还原后强制重建复跑全绿 |

### 判据（照抄基准的三格，包括两格看着反直觉的）

`src-tauri/src/paths.rs`：`parent_of` → `normalize_key` 找父目录 → 子项名（大小写折叠）命中即放行；
**这轮扫描被 `maxFiles` 截断过**则退化成「父目录在树上即放行」。退化照抄的理由是基准自己那句：
*这是只读工具，打开不等于删除*。归一化只有一把（`deepclean_rules::engine::normalize_key`），
与引擎的认领表、`TreeSource` 同源。

两条命令共用一个 [`guard`]：**拒绝那一格做成了可单测的纯函数**。它必须这么做，因为
`E_UNTRUSTED_PATH` 在界面上走不到 —— 渲染端只能从已扫的树里拿路径，而那正是这道闸存在的全部理由。
所以真机给不出"点了一次拒绝"的证据，这里也不假装给得出；它由
`the_command_gate_opens_for_tree_paths_and_refuses_everything_else` 钉住，反例里点名
`C:\Windows\System32\cmd.exe`、`D:\range\evil.exe`、截断树上不存在的深层项、空串、`not-a-path`。

### 真机两相（看的是"开出去的是谁"）

1. 右键地图上的文件格子（夹具：`Alpha.txt` 2 MB vs `Inbox` 512 B，格子大小差 4000 倍，
   点画布中心必是那个文件）→ 菜单出来 → 点「打开所在位置」→ 新多出一扇窗口，
   标题逐字是 **`m5e-paths - 文件资源管理器`**（`explorer /select,<父目录>` 的形态）。
2. 同一格 → 点「打开」→ 新多出一扇窗口，标题逐字是 **`Alpha.txt - Notepad`**
   （走 `ShellExecuteW`，与 Electron `shell.openPath` 底下同一个 API）。
3. 收尾只 `PostMessage(WM_CLOSE)` 关**这次新多出来**的那两扇窗口 —— 不 `Stop-Process` 杀
   `explorer.exe`：那会牵连桌面。
4. 零删除反证：两个夹具文件逐名点名还在盘上。

窗口枚举第一版是手写 `EnumWindows` + PowerShell 脚本块当原生回调，跑出来只捞回一个标题 `"m"` ——
换成 UIA 根元素的顶层子列表（标题 / pid / 句柄都在 `Current` 上）才可信。这条与
「native 回调当 PowerShell 委托不可靠」一起记着。

### 代价

- 判据里那次 `iter_dirs()` 是**线性找父目录**（一次点击只问一遍，为它建一张 30 万条的索引不划算）。
  十万级目录的机器上这是一次几十毫秒的扫描，发生在右键菜单之后、不在任何热路径上。
  M5-F 那格「十万级不卡界面」会把它一起量掉。
- `reveal_in_explorer` 不看退出码：`explorer.exe` 成功时也常给非 0，而基准那侧返回 void。
  报「打开失败」是假话，报「打开成功」同样是假话，所以两条都不报。

### 落点与三条边界

`tree_index.rs::level_of` 多收一个 `excluded: &BTreeSet<i64>`，只在**视图口径**上生效；
`children_of`（计价路径）一个字节都不动。守恒等式换成三条：

```
children.len() + folded_count + excluded_count == total_children
Σchildren + folded_bytes + excluded_bytes      == Σchildren_of(dir_id)
```

被排除的项**不占 `cap` 名额**（`folded_count` 从 `kept.len() - take` 算，不是 `total - take` ——
写成后者会把被排除的重复计一次，守恒等式当场多出一格，本次实测红出来的形状）。
`canExclude` 的判据只有一处（`service::set_excluded`）：必须是树上真存在的目录、且**不是扫描根**。
回 `false` 必须把拒说出来，不许静默成功 —— 渲染端那句「没有生效」的横幅靠它。

### 真机撞出来的一个真缺口（不是脚本错）

第一版真机跑出来：格子确实消失了，**横幅却永远出不来**。根因是 Rust 的 `ChildrenPayload`
**少了 `sessionExcludedCount` / `sessionExcludedBytes` 两个字段** —— 侧栏那句「已排除 N 个目录
（本轮累计）」读的就是它们，而单测只查了本层那两份 `excluded_count/excluded_bytes`，
所以两边都"绿"。修法没有停在"命令里记得补一下"：那两格被做成 `payload` 的**必填参数**
（`session_totals`），漏传直接编译不过。X5 这条变异就是把它退回 0，一条判据当场红。

截图那一格同时给出两件可见的事实：地图只剩 `Keep 1.0 MB`，而顶栏仍写 **`占用 9.0 MB`**
（父级容量没被扣掉），`Top` 列表里 `Keep` 仍是 **11.1%**（分母是整棵树）。

### 两处自己的错（都不是产品错，记下来免得再犯）

- 测试第一版拿 `total_bytes > 0` 当"夹具喂出了东西"的判据，而它传的是**空勾选** ——
  空勾选时 `total_bytes` 本来就该是 0。改成真勾选一条规则。
- 顺带修掉 D2 留下的形状错：`assemble_dev_env_view` 给 `build_preview` 传的是
  `{selection:{items:[]}}`，而那个形参**就是勾选对象本身** —— 套一层会让 `items` 缺失，
  引擎白记一条 `unknown-rule` 拒绝（数字不受影响，因为全量口径在 `finding_bytes` 上）。
- 脚本侧：`$R`（夹具根）与 `$r`（菜单矩形）是**同一个变量** —— PowerShell 变量名大小写不敏感，
  于是"零删除"那一步去查 `355,836,287,47\BigHide\payload.bin` 是否存在。改名后全绿。

### 落点

`crates/scanner/src/heap.rs`：容量固定的小顶堆（`TopHeap`），基准是 `core/scan/heap.ts`。
三条形状各对应一种会骗人的结果，都写进了注释并被用例钉住：堆序 ≠ 排序（`entries()` 交无序快照）、
**只在严格大于时替换**（写成 `>=` 会留下"最后见到的 100 个"，而按 size 对账两边一样）、
`size > 0` 才入堆（0 字节文件在满盘树里能有几万个）。

`scan.rs`：`ScanOptions::top_n`（默认 100，与 TS `o.topN ?? 100` 同一个数）；推入点在文件分支里，
先问 `wants(size)` 再分配 —— 这是本侧唯一一处比基准多做的判据（省掉每条目录项一次 `clone` + `join`），
**不改变结果**：`wants(s)` 与"推进去会被丢掉"恰好互补。`ScanTree.top` → `TreeIndex::top_files()`，
查询端因此零走盘。

`src/top_files.rs`：`apply_top_query`（扩展名补点小写 → 前缀**段边界**匹配 → `minSizeBytes` 是 `>=`
→ 排序 → 截断）。**过滤在截断之前**就是判据本身：先取前 100 再过滤，和先过滤再取前 100，
是两张不同的表（`filters_run_before_the_limit_not_after` 专门造了一份能区分的夹具）。

### 一处有意的分叉（写在文件头，不留成"看着一样就算过"）

并列（size 相同）时的次序：TS 用 `localeCompare`，这里用字节序。只影响并列行谁在上面，
不影响集合成员、不影响任何数字。要复现 `localeCompare` 得引一个 collation 库，为视觉顺序
付这个代价不值。

### 真机（独立口径 = `Get-ChildItem | Sort Length -Desc`）

夹具 104 个文件：`big.iso` 120 MB、`mid.zip` 6 MB、`small.txt` 1 MB + 101 个约 1 KB
⇒ 堆容量 100 **真的截断一次**。

- 表头那句 **「100 项 · 合计 127.1 MB」**：不多不少 100 行。
- 前三行 `big.iso 120.0 MB` / `mid.zip 6.0 MB` / `small.txt 1.0 MB`，与 `Get-ChildItem` 逐条一致。
- 第 101 名（最小的那个 `tiny003.dat`）**不在表里** —— 容量这条在真机上生效，不只是单测里生效。
- 门槛切到 **「≥ 100 MB」→ 只剩 `big.iso`**，`mid.zip` 消失；切回「不限」又回来。
  这一相第一版用 `ValuePattern.SetValue` 改下拉，页面纹丝不动：Chromium 的 `<select>` 被 UIA
  改值时不派发 React 监听的那个 `change` 事件 —— 与设置页同一形状，那里也是**真点选项**才验得到。
- 零删除反证：三个大文件逐名点名还在盘上。

### 一处刻意的偏离：原生保存框在本机弹不出来

基准那侧点「导出 JSON」弹 `showSaveDialog` 让用户选位置。这一侧换成**服务端定位置**：
`<appData>\reports\deepclean-report-<scanId>.json`，并把那个位置原样念回界面。

探针事实（不是推测）：`tauri-plugin-dialog` 2.7.3 + 本机 (Windows 11 / WebView2 / tao)，
`save_file` 等 25 s —— 本进程除主窗口外没有任何额外顶层窗口（只有一个 `Tao Thread Event Target`），
回调也从不触发，命令于是永远不返回，界面连「已取消」都念不出来。
**一条没人能在真机上验完的交互通道，比一条位置固定但端到端验过的通道更差。**

代价，点名：① 用户不能选别的位置，要挪得先落到 `reports/` 再自己挪；② 覆盖写同名文件
（同一趟扫描导两次是同一格，第二遍盖掉第一遍 —— ② 那一相验的就是这个）；
③ 将来若把保存框修好，这一格的落点逻辑要连着改，别留两份真相。
登记在 `commands.rs::dc_export_report` 的注释里，与本文互为镜像。

### 真机三相（`scripts/m5e-report-e2e.ps1`，全程零删除）

落点由服务端定，所以证据链刻意是"界面说什么位置 ↔ 那个位置真有什么"，两边都不许脚本猜：

1. **① 界面点名位置**：那句「已导出：C:…\reports\deepclean-report-t1791805706264-0.json」
   按全角冒号切出来，`Test-Path` 那个路径 —— 盘上真有。截图 `m5e-report-exported.png`。
2. **② 覆盖写**：再点一次，界面念出的还是同一格；且 `reports/` 里**本次只新增 1 份**，
   新增那份的文件名逐字等于界面点名的那个（跑前先把目录里原有的文件名记下来 ——
   上一次失败回跑留的孤儿不能被判成本次的产出）。
3. **③ 内容与独立口径对账**：`Get-ChildItem -Recurse` 现数 `files=3 / dirs=2`，
   报告里 `counters.files=3 / dirs=2`；`totalBytes=606208` = 界面那句「592.0 KB」；
   `schema` 串逐字对；`denied=0` 那一格 `sample` 与 `sampleOverflow` **两个键都不在**；
   `peakRssBytes` 是 `null`；`treeLimits` 写出 3/12；`topFiles` 3 行。
4. **零删除反证**：三个夹具文件逐名点名还在盘上（导出是只读通道，没有任何执行入口被点过）。

**第一版这一相是我自己错的**：断言写成 `dirs == 独立数 + 1`（"报告该含根"），当场红。
口径写在 `shared/types.ts:186`「子树目录数，**不含本目录自己**」，而 `Get-ChildItem -Recurse -Directory`
同样不含根 —— 两边都是 2，谁也不加 1。独立对照其实早就在屏幕上：首页那张卡同一趟扫出的
「已扫描目录 2」。改断言而不是改实现。

### 与 TS 的零容差对账（这一步买到了什么）

`src-tauri/tests/parity_report_ts.mjs` 把夹具喂给**真的** `core/report/scan-report.ts`，
Rust 侧 `report::tests::with_ts_zero_tolerance_on_the_same_tree` 把同一份夹具喂给自己的 `build_report`，
四格 case 逐字段比。归一化**只有一格**：数字的**表示**（`elapsedMs=0` 那格 TS 写 `10000`、
Rust 写 `10000.0`，是同一个数的两种字面量）—— 值一格不抹，差 1 字节照样红。

夹具刻意包含：16 个子目录（**超过**每层 12 的上限，裁剪真发生）、并列在 200 字节的 `da`/`dZ`
（`cmpPath` 那一支：留下 `da`、折掉 `dZ`，两侧同判）、四层深的一条链（到 `maxDepth` 那层
**没有** `children` 键）、`denied=0` 与"压根没有清单可说"两种缺席、`elapsedMs=0` 的兜底、
以及**故意不排序**的 `topFiles`。反空跑那条用例（`the_fixture_actually_exercises_the_interesting_cells`）
逐格检查这些形状真被走到，不看结论看输入。

**三条变异只有对账抓得到**（手写用例三条全绿）：

| 变异 | 为什么单测抓不到 |
| --- | --- |
| R17 `round2` 不 round | 手抄的夹具速度全是 10/2000 ms 这种整除的数，`5.0` 与 `5.0000…` 同形 |
| R18 `topFiles` 被偷偷逆序 | 唯一断言是"非空" |
| R19 目录 `size` 少算本层文件 | 断言是 `size > 0`，少算照样 > 0 |

### 边界

- 报告导出的是**扫描**（计数、错误分账、目录树摘要、Top 榜），不含 findings / 预览 ——
  那是清理页的账，两份各说各的。
- `dirs` 不含扫描根（口径见上）；`treeLimits` 必须写出来，读的人才知道这份 JSON 不是全树。
- `peakRssBytes` 交 `null`：这一侧没采。基准的调用点（`electron/main/ipc-register.ts:50`）
  今天也传 `null`，所以两侧在真机上是同一个数；差别只在**这一侧没有那条管道**，
  将来要接得先给壳层加量内存的链。
- 截图 `m5e-report-exported.png` 里有本机 Windows 用户名 —— 它就是这一相被验的那个位置，
  不是漏处理的凭据；登记在此以免日后有人以为没人看过这张图。
- 真删授权不变：本刀零删除代码、零执行入口点击。
