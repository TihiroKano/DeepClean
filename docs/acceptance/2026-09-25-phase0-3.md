## §35 第一验收标准四项

1. **能不能扫描真实 C 盘** —— 通过。106 个权限错误全部「记录 + 跳过 + 继续」，任务未失败（§8）。
2. **能不能正确统计目录大小** —— 通过。见 results.md 第 1、7 节。
3. **能不能处理大量文件而不冻结 UI** —— 通过。渲染进程独立，扫描全程切页/钻取/右键均响应；
   人工判定，**不用 rAF 帧率断言代替**（后台标签页节流会给出假绿灯）。
4. **能不能通过 Treemap 快速找到真正占空间的位置** —— 通过。首屏一眼定位 Users + Windows 占掉 64.3GB 的 75%。

## 安全边界（§28 原则一）

- 全仓 `core/ electron/ src/ shared/` **零删除调用**（`rm(`/`unlink`/`rimraf` 无命中）。
- `加入清理列表`、`排除扫描` 两项右键菜单**刻意置灰**并注明属 Phase 4+；首页「可清理空间」为占位文案，
  未用任何假数字填充。`DetailModel.deletable` 是字面量类型 `false`。
- `shell.openItem` / `revealInExplorer` 走 `knownPath` 白名单，拒绝不在扫描树内的路径（`E_UNTRUSTED_PATH`）。

## 已知偏差（对外要认）

表观大小 ≠ NTFS 磁盘占用大小（`WinSxS` 等压缩目录与资源管理器显示值差异明显）；单层最多 1200 tile，
超出折入最后一块；无 react-router、无自定义标题栏；`CPU占用/磁盘读取` 两项为人工读数。
详见计划「已知偏差」节。
