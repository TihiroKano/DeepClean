**一句话**：第二轮按说明 §13 把蓝撤走之后，底色退成近似均匀的 `#0e0f11`，而 `backdrop-filter`
糊的正是身后那层 —— 一层均匀的黑糊出来还是均匀的黑，"玻璃"因此读成一块略亮的黑。

## 1. 起因：第二轮那条判据赢了，界面输了

第二轮把配比做成了可机判的一对（面板 `B−R ≤ 12`、按钮 `B−R > 12`），现跑 `panelBlue:0 / ctaBlue:168`，
**判据全绿，而它没管住的那一半塌了**：为了"80% 灰黑"，`.dc-app` 那层底被压到只剩两团
alpha .10/.07、圆心落在窗口上沿之外的雾 —— 整窗几乎是同一个值。于是：

- `--glass-tint-page: .055` 的白纱铺在均匀的黑上 = 一块略亮的黑；
- `blur(28px)` 糊不出任何东西；
- 说明 §10 那五条"半透明 / 背景颜色可以穿透 / 非均匀透明度 / 边缘高光 / 环境光"，
  有两条（穿透、环境光）**根本没有可穿透、可反射的东西**。

教训一条：**成对的判据只钉住它量得到的那一维。** `B−R` 管的是"蓝多不多"，
它对"黑得有没有层次"完全失明，所以那一轮可以一边全绿一边把玻璃做没。

## 2. 环境光（`global.css` 的 `.dc-app`）

四层，从上往下压：

| 层 | 给什么 | 为什么这个值 |
|---|---|---|
| 内联 SVG 的 `feTurbulence` 颗粒，140 px 一 tile，`stitchTiles` | 打断渐变的色带 | 一条 20 阶的竖直渐变在 8 位色深上会画出一圈一圈等高线，而等高线正是"廉价深色主题"的读法。`opacity .04`，读到的不是噪点，是"这不是纯色" |
| 左上主光 `rgba(126,152,192,.14)` @ `10% −8%` | 光从上面来 | 圆心在窗口外，所以最亮处落在标题条上方 |
| 底部反光 `rgba(78,98,132,.17)` @ `48% 116%` | 主体之外的一点纵深 | 同一条理由，圆心在下沿之外 |
| `linear-gradient(178deg, --bg-top 0%, --bg 44%, --bg-deep 100%)` | 一条竖直区间而不是一个点 | `#1a1d24 → #101216 → #08090b`，明度跨度约 20/255 |

**两团雾的圆心位置不是审美选择，是被一条硬约束定死的**：右上角那 138×40 由 OS 按**一个纯色**画
（`titleBarOverlay.color`），所以那块区域必须落不进任何一团雾 —— 它得恒等于渐变起点。
这条写进了 `electron/main/index.ts` 的 `titleBarOverlay` 注释，值 `#1a1d24` 与 `--bg-top` 逐字相同。

底色不许走 `.dc-app::before`：§4 地图叠放第 ⑦ 道判的就是那两个伪元素没有 `content`
（桌面位图那一版就是靠一个整窗覆盖层盖住地图的）。所以只能压在 `background-image` 列表里。

## 3. 这一轮唯一可机判的那条：环境光不许退回均匀纯色

说明里"高级感""通透"都量不出来，但**"背景是不是均匀的"量得出来**，所以做成了一条像素判据
（`electron/main/index.ts` 的 §23 环境光）：

```
在首页内容下方那条确定没有元素的空白带里铺 10×6 的格
每格取 12 CSS px 见方的「块均值」 → 60 个明度值
极差 spread 必须 ≥ 3，均值必须落在 6–60
```

**为什么必须取块均值而不是逐像素**：颗粒自己的逐像素极差有 6–10 阶。逐像素采样的话，
"把渐变全删光、只留颗粒"这一族改法会喂饱判据 —— 那正是假绿灯。144 个样本的均值把零均值
高频噪声压到 0.5 以下，只剩下低频明暗，而那才是这条判据要的东西。

**阈值 3 是量出来的**，两条各跑了一整遍 `--shot`：

| 装的东西 | `spread` | `mean` |
|---|---|---|
| 这一版真值 | **5.12** | 18.53 |
| `.dc-app` 的 `background-image: none`（只剩一层纯色） | **0.00**（60 个块均值逐字相同） | 17.86 |

还原后重跑 `EXIT=0`。阈值坐在 3，两边各留一倍以上。

取不到空白带时**报"无证据力"而不是报红**（窗口再矮一点、或首页再多一行内容，那条带就没了），
同 §4 地图叠放第 ⑧ 道的写法 —— 那种情况下任何结论都是编的。

## 4. 玻璃配方（`glass/tokens.css`）

- 新增 `--glass-specular`：左上角一小片镜面。它和 `--glass-sheen` 不是一件事 ——
  sheen 说"光从上面来"，这一层说"光是从**左上**来的"。方向感是"环境光"里"环境"两个字
  唯一还能用 CSS 表达的部分。
- `--glass-inner` 中间多了一条 `inset 0 0 22px rgba(255,255,255,.018)` 的内散射：
  只有上下两条硬线的话读起来是"贴纸"，不是"板"。
- 外投影第二条改成**带负扩散半径**（`0 20px 46px -16px`）。不带负 spread 的话投影均匀围一圈，
  那读起来是"卡片在发光"，正是 §10 明令禁止的那一条。
- `--glass-blur-page` 28 → 30。**抬它不是因为 28 不够，是因为第二轮身后没有东西可糊**；
  底重做出明暗之后这个半径才第一次在做事。
- 侧栏从一层 `.022` 的白升成同一族材质（渐变 + `blur(34px)` + 一条亮线压一条暗线的右边线）。
  它原来是"窗口左边贴了一张不透明的黑纸"。
- `.dc-menu` / `.dc-mapctl` 的**不透明度一档没降**（V0.8 为这对数值量过对比度，结论仍站着），
  只补了边缘高光与内应力。
- "折射"仍然没有做，仍然不许在注释里把它写成折射（真折射要 WebGL，V0.8 裁定 3 已否）。

**`align-items: center` 不是随手挑的**：第一版做成 `flex-end`，于是右侧那列（CTA + 两句脚注）
比左侧那列（范围，两行）高六十来像素，底对齐把矮的那侧往下推 —— **空洞只是从右边搬到了左边**。
真机截图抓到之后才改成居中，并把那两句脚注挪出这一行。

**代价（两条）**：① 一次顺利完成的扫描之后，首页不再显示「已扫描目录数 / 跳过项目 / 权限错误」
这三个数。它们没消失，地图侧栏 §15 那一栏与导出的 JSON 报告里都还在；而只要真跳过或读不到，
这一格就还会回到首页。② 「本次可清理」的口径从屏幕挪进悬停，不看 tooltip 的人读不到它怎么算的。

## 6. 两处漏改的蓝残留 + 一档颜色收敛

第二轮那条 `panelBlue` 判据读的是**主面板**的 computed `background-color`，所以它抓不到别处：

- `.dc-input` 还写着 `rgba(4, 18, 46, .55)`（B−R = **42**）—— 选「指定位置」之后那个输入框，一点就看见；
- `.dc-tip` 还写着 `rgba(11, 32, 74, .92)`（B−R = **63**）—— 地图上悬停就弹出来。

两处都退回中性。`.dc-tip` 属浮层档，**不透明度没跟着降**（§4 那条对比度结论仍然管着它）。

环中心那个 24 px 的百分比：`--usage-high` 从 `#f85149` 收到 `#e07a6c`（`--usage-mid` 同方向）。
它是全窗口最响的一个东西，响过了 —— 说明 §13 的配比里没有"亮红"这一档。
**"≥90% 才点亮"这条判据一个字没动**，动的只是它发声的分贝。代价：严重与不严重的第一眼区分度弱了。

顺带：`input[type=radio|checkbox] { accent-color: var(--accent) }`，否则 `color-scheme: dark`
给的是系统那枚蓝。

## 7. 只有真机整窗截图看得见的第二条（延续第二轮 §7 的方法论）

四道闸对它的接缝一律失明。走 `CopyFromScreen` 抓整窗，再用 `tmp-shots/seam-probe.cjs` 解 PNG 逐点比：

```
y=18px  us120=#1a1d24 … us0=#1a1d24 | OS-20=#1b1e25 … OS-200=#1b1e24
```

接缝最大 1–2/255，肉眼不可见。**注意颗粒那层是有均值的**（`opacity .04` 的中性噪声叠上去约 +2～3 阶），
所以"渐变起点 = overlay 色"这个等式其实差着两三阶 —— 量出来在阈值以下，但**别再往下加颗粒**。

## 9. 判据变更

`--shot` 的 §23 首页那一跑**一条没删、一条没改**：`panelBlue:0`、`ctaBlue:168`、`tracks:2`、
`sideW:84`、8 条导航标签全非空、`onCount:1`、donut 两个 stop 解析出颜色 —— 全部照旧绿。
**新增**一条（§23 环境光，见 §3）。

`.dc-nav-on` 与 `.dc-card` 同一条纪律：底色写 `background-color`、高光另起 `background-image`。
合成一条 `background:` 简写会让 computed `background-color` 退回 `rgba(0,0,0,0)`，
而 `onBg` 正打进 §23 的日志 —— 它现在只看不判，但一条恒为 0 的 alpha 会让下一个人以为胶囊没上色。
现值 `onBg: rgba(255, 255, 255, 0.075)`。
