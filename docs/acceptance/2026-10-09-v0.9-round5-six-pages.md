## 1. 做法：改原语，不改六页

六页共用的表面只有六个，逐个改页面会写出六份真相。所以这一轮全部落在共享选择器上：

| 原语 | 谁在用它 | 改了什么 |
|---|---|---|
| `.dc-bar` | 地图 / 大文件 / **清理记录的筛选器行**（`dc-bar dc-journal-filters`） | 实心 navy → 玻璃带（渐变 + `blur(26px)` + 上沿 1 px 内高光） |
| `.dc-table th` | 五张表 | 实心 navy → **半透 + `backdrop-filter`**：吸顶行糊住从它底下滚过去的行，但仍然透出环境色 |
| `.dc-side-panel` | 地图详情侧栏 | "窗口右边贴的一张不透明纸" → 首页次级卡同族材质 |
| `.dc-clean-total` / `-task` / `.dc-estimate` | 垃圾清理页三块汇总 | `--bg-2` + `border-radius: 6px` → `--glass-fill-quiet` + 圆角 token + 内应力 + 糊 |
| `.dc-devenv-group` | 开发环境七个生态 | **今天根本没有底色规则** → 一张次级卡（分组感第一次成立） |
| hover 色块 ×5 | 面包屑 / Top 行 / 菜单项 / 表格行 / 勾上的行 | 实心 `--bg-2`/`--bg-3` → **加亮不遮盖**的光洗 |

**为什么 hover 必须从实心改成洗色**：这些表面本身现在是半透明的，一块不透明的 hover
压上去等于**把身后那层丝绒糊死一小块** —— 悬停一下反而更不透。
`.dc-clean-on`（勾上的行）例外地多给一条 `inset 3px 0 0` 的左端亮边：
"哪些条目会被删"是那一页最要紧的一件事，不能只靠 6% 的亮度差。

## 2. 只有真机截图看得见的两条（41 步判据一条都没红）

### 2.1 上一轮我自己加的 `nowrap` 把一列撑到按钮上面去了

第三/四轮为修「7.0 MB」被拆成两行，给 `.dc-num` 整类加了 `white-space: nowrap`。
全仓只有**一格**会往 `.dc-num` 里放整句人话 —— `DevEnv.tsx:207` 的 `devEnvBytesText`，
最长那句是「这棵树上没有它的地盘（扫的是 D:…\Users\Kano）」。nowrap 让那句横着溢出 14%
的列宽、**压在右边「动作」那列的两个按钮上面**（`39-devenv-page.png` 上两行字叠在一起）。

`--shot` 的 §3.6 那几步读的是 `textContent` 与 `residue/missing` 计数，**不读几何**，
所以整套跑完零红。修法是 `.dc-devenv-group .dc-table td.dc-num { white-space: normal }`
—— 那一列 154 px 宽，短数字本来就拆不开，撤掉 nowrap 不会退回去。

**留一条规矩**：给"数字列"上的类加排版规则之前，先 grep 有没人往它里面放散文。

### 2.2 `.dc-journal` 这个根类名从 V0.5 起一条规则都没有

和 `.dc-page` 在第二轮被补样式之前是同一个坑：**类名挂在根上、两份样式表里没人理它**，
于是清理记录页是贴着窗口边缘画的。这一轮给它一条真规则时顺带撞上第二个问题：
`.dc-view` 是 flex 列，而 **flex 项默认 `min-width: auto`** —— 一张比视口宽的表格会把
**整个根**撑宽，横向滚动条因此出现在页面上而不是 `.dc-table-wrap` 里，
连带把页脚那两句散文推出右边界。解法是 `min-width: 0` + 让表格在自己的容器里滚。

`.dc-large` 同一条理由一起补了 `min-width: 0` 与页边距。

## 3. 勾选框与单选钮改成自绘

只设 `accent-color` 的话，**未勾选**那一面是 Chromium 按 `color-scheme: dark` 自己给的深灰，
压在钴蓝底上读起来是**一块发褐的方片**（`10-cleanup-list.png` 整列都是）。
而"哪些条目会被删"是那一页最要紧的一列，它不该看起来像坏了。

现在自绘：15×15、玻璃井底、勾上走品牌蓝 + 一枚 SVG 对勾。
**对勾用 `background-image` 而不是 `::after { content }`** —— 本项目有一条硬规矩是界面文字
不许搬进 CSS 生成内容（`--shot` 靠 `textContent` 找导航入口）。对勾不是文字，
但用同一个形状去画它，下一个人就分不清哪种 `content` 是允许的。

`input:disabled` 补了 `opacity: .34` —— 🔴 那一行**根本勾不动**是 §28 原则四的界面半边，
以前置灰看不出来。⚠️ 尺寸写死 15×15 且 `flex: none`：`--shot` 有 20 多步在点
`.dc-clean-check input` 并读 `checked`，命中面积一改小那些步就点空。这一轮整套重跑过，零红。

## 5. 刻意没动的三处

1. **地图几何一个字没改。** `.dc-treemap` 仍铺满容器、canvas 仍不加任何内边距 ——
   §4 那八道叠放判据与命中测试（`34 文件格 => x:459` 那一族）全都假设 canvas 填满容器，
   而"面积 = 容量"是这产品唯一的可读性契约。让它贴着窗口边缘是 SpaceSniffer 那一族的常态，
   这一轮的验收图里也没有地图页。
2. **`.dc-mapctl` / `.dc-menu` 仍然保持中性深灰、没跟着变蓝**（第四轮就定了，理由没变：
   它们浮在地图上，压一层蓝会把格子色相带跑）。**这不是漏改。**
3. **重复文件页没单独改。** 它的表格与按钮全走上面那些原语，改原语就跟着好了 ——
   这正是这一轮选择改原语的原因。

## 6. 收尾时补的两件（人类伙伴看图提的，2026-10-09 上午）

### 6.1 「怎么是黑的、字标哪去了」—— 是旧构建，不是回退

人类伙伴贴的那张截图是 **84 px 纯图标栏 + 黑底 + 红色百分比**，那是第三轮之前的形状。
查下来：他双击的是 `dist/DeepClean 0.1.0.exe`，**构建于 10-08 21:28**，而第三/四/五轮
（`0889e9f` `54017e6` `af1f10b`）全在 10-08 22:30 之后 —— **从没进过那个 exe**。
`out/`（`npx electron .` 读的那份）是新的，`dist/` 是旧的。

**这一轮已经 `npm run dist:portable` 重建**（现产物 10-09 11:21）。
留一条给以后：**改了 UI 之后，只要人类伙伴可能去双击 exe，就必须一起重建 `dist/`**，
否则他看到的是几轮之前的界面，而四道闸全绿 —— 因为它们跑的是 `out/`。
`dist/` 不在版本控制里，**没有任何一道闸能发现它过期**。

### 6.2 侧栏品牌位：图标删掉，字标放大并照应用图标上色

`App.tsx` 里那个 `<img className="dc-brand-img">` 删了，`brandUrl` 的 import 一起删
（`noUnusedLocals` 会拦，所以不会留下悬空 import）。字标从 15 px 放到 **20 px**，
颜色走 `linear-gradient(96deg, #ffffff → #dcecff → --accent-2 → --accent-3)` +
`background-clip: text`，取的就是应用图标上那行「Deep 白 / Clean 青蓝」。
`color: var(--fg)` 那行**留着当兜底**：`background-clip: text` 万一不生效，没有它整个字标
会变成一片空白 —— 而"看不见"和"没渲染"只有截图分得出来。

**应用图标仍然在首页问候行那 56 px 的砖上。** 那里够大，图标底部自带的 "DeepClean"
字样读得出来；侧栏那一格只有 30 px，那行字会糊成一团纹理，还和右边的字标重复 ——
这正是第四轮裁掉局部的原因，也是这一轮把侧栏那处彻底删掉的原因。
`assets/brand-glyph.png`（裁掉的那版）随之删掉，`assets/brand.png`（256² 整张）留着给问候行。

真机整窗截图量过字标那条带：从左到右 `#ebf4ff → #8cc0ff → #77b5ff`，渐变确实走在字上。
四道闸重跑：typecheck 0 / 1083 passed·64 files / build 0 / `--shot` EXIT=0。
