# 2026-10-27 晚 授权卡第二轮：分相文案 + 3–7 s 随机 + 已激活不再画输入框

**一句话结论**：白天那一版把授权卡「校验中」画成了一个环，晚上人类伙伴要三件事 ——
**加载时长不定（3–7 s 随机）**、**加一句「服务器通讯中」**、**已激活之后不再显示激活码与输入框**。
三件都落在**呈现层**，服务端一个字没动；结论仍只由 `afterActivate` 收到的**重读状态**决定，
那段被拉长的等待**不改变任何判定**。

> 白天那一轮（三块卡片 / 壁纸 / 毛玻璃 / 莫比乌斯环五版）见
> [2026-10-27-settings-page-rework.md](2026-10-27-settings-page-rework.md)。本文只记晚间追加的部分。

## 1. 人类伙伴给的原话

> 激活的加载最好时间不定，3-7 秒随机。
> 加载动画加个服务器通讯中......，这点点要会动。
> 激活后不再显示激活码和输入框，只保留已激活字样。

三句各自对应本文 §2 的一节。

## 2. 改了什么

### 2.1 时长：3–7 s 随机，两相按 4:6 分

`LicenseCard.tsx` 新增 `rollDurations(rand = Math.random)`：

```
total   = 3000 + rand() * 4000      // 闭区间两端都到得了
network = round(total * 0.4)
verify  = round(total) - network    // 两相相加逐字等于 total
```

**为什么是随机而不是固定 5 s**：固定时长会在第二次激活时露馅 —— 用户掐一次表就发现
"每次都一样"，那反而说明这个时长与真实工作量无关。随机让它读起来像"这次网络快一点"。

**为什么兜在界面而不给服务端加 `sleep`**：后端那条链没有需要等的事 —— 探测点第一个通了
就返回，码表是本地 65 KB，签名是微秒级，真耗时几十毫秒。往服务端塞 `sleep` 会把
「激活要 3 秒」变成一句假话，还会污染 `netprobe` 的探测顺序与 `activate` 的写点顺序。

**代价写在明处**：这两段等待**不改变任何结论**。`ok:true` 而重读到 `unlicensed` 时，
卡片照样说「未激活」—— 这条由 `license-card.test.tsx` 那三条「回执不赢，重读赢」钉着，本次没动。

### 2.2 文案：两相各自一句话

| 相 | 文案 | 对应链上真实发生的事 |
| --- | --- | --- |
| `network` | 正在与服务器通讯中 | `netprobe` 的 TCP 探测 |
| `verify` | 正在校验激活码 | 码表比对 + 设备签名 |

两段的失败原因完全不同，用户看到的进度也该分开。**网络那一相不许同时说「校验激活码」**——
那是下一步的事，先说出来就是提前报进度（判据有反向半边）。

三个点是 `.dc-dots` 的 CSS 动画，**不是**把省略号写进字符串靠计时器换文本：
后者每换一次都会重排这行字，且判据只能靠假计时器测。

`LicenseBusy` 从 `LicenseCard` 里抽成独立文件。理由不是"看起来干净"：
`Settings → LicenseCard`，若 `LicenseBusy` 留在 `Settings.tsx` 里就成环，
ESM 下表现为其中一侧拿到 `undefined`，而报错信息指向别处。

### 2.3 已激活之后不再画输入框与按钮

`{!licensed && (<div className="dc-actions">…</div>)}`。

**为什么是"不渲染"而不是 `disabled`**：一张永远点不动的输入框会让人以为还能再激活一次，
而实际上同一个码在本机只会走幂等分支（`AlreadyActive`，一字不写）。留着它等于给用户一个
假的可操作面。

**这是这块卡片唯一可逆的地方**：授权一旦失效（`status` 变成 `invalid`），`licensed` 就是
false，输入框自己回来，用户不必重开设置页。这一条有专门判据（见 §3）。

同一句「需联网激活验证」也挪进了 `!licensed` 分支：已激活之后没有"点激活"这个动作了，
那句话就成了一句关于不存在的按钮的说明。

## 3. 判据（`settings-page.test.tsx` 14 → 21 条；`license-card.test.tsx` 17 条不变，改写 2 条）

新增的 7 条全部落在 `settings-page.test.tsx`（白天那版 14 条，见
[settings 验收 §3](2026-10-27-settings-page-rework.md)）：

| # | 钉住什么 |
| --- | --- |
| 1 | 总时长落在 [3000, 7000]，且**两端真到得了**（`rand=0` ⇒ 3000、`rand=1` ⇒ 7000） |
| 2 | 两相都非 0（任一相为 0 会让那半句文案一闪而过） |
| 3 | 抽 20 次不止一个总值 —— 固定时长会让这条红 |
| 4 | 两相文案分得开，各带**反向半边**（见 §3.2） |
| 5 | 三个点各有自己的 `animation-delay`，且 `@keyframes dc-dots-pulse` 在 |
| 6 | 已激活之后：输入框、按钮、「需联网激活验证」**全都不再渲染** |
| 7 | 授权失效（`invalid`）时输入框**自己回来** —— 不必重开设置页 |

**改写的 2 条**在 `license-card.test.tsx`（条数不变，17 → 17）：

- `licensed → 念得出「已激活」与激活日期、设备指纹` ⇒ `licensed → 只念「已激活」；
  激活日期与设备指纹那两格已被删掉，不许回来`。这是**需求变更**：人类伙伴点名删掉那两格，
  所以断言从"必须在"翻成"必须不在"，反面那半边比原来更严；
- `那一行改口了：说清"探测会连公网…"` ⇒ `只说「需联网激活验证」，旧的实现解释一句都不许回来`。
  `TCP` / `不发送任何数据` / `激活码不上传` 这三句仍然是真的（`netprobe.rs` 那条链还在跑），
  只是不再摆在授权卡上。

其余 15 条一字未改；`state` 夹具补 `busyPhase: null` 是结构变更带来的**机械**改动，不算判据变化。

### 3.1 `rollDurations` 收一个 `rand` 是为了判据能确定地量到边界

拿 `Math.random` 跑一百次也能看出界，但那是一条**统计判据**，会偶发红。
收参数之后 `rollDurations(() => 0)` 与 `(() => 1)` 各自钉住一端 ——
这钉的是"闭区间"，不是"落在 [3000, 7000)" 那种半开区间的假边界。

### 3.2 反向半边

- 网络那一相 `not.toContain('正在校验激活码')`；判定那一相 `not.toContain('服务器通讯中')`。
  只写正向的话，两相写成同一句话也会全绿。
- `reduced-motion` 那条同时钉**能停**（`animation: none`）与**停完仍然可见**（`opacity: 1`）——
  停成透明的点等于把半句文案删了。

### 3.3 取 reduced-motion 块必须取全部

`global.css` 里有多处 `@media (prefers-reduced-motion: reduce)`（`.dc-jump-dot` 那组也在）。
用**第一个**匹配会读到别人那一段，于是那条判据在真出错时也是绿的。
判据改成 `matchAll` 取全部再拼接，这个坑写进了用例注释。

## 5. 未做 / 已知代价（如实登记）

1. **这一轮没有真机截图**。三张 `assets/settings-*.png` 是**白天**那版（19:03），
   里面还没有分相文案、也没有"已激活不画输入框"这一态。
   晚间的视觉证据**一格都没有** —— 判据是渲染闸（`renderToStaticMarkup`）与源码闸，
   它们证明"渲染出来是这几个字"，**不证明"屏幕上看起来对不对"**。
2. **3–7 s 这个时长本身没有产品依据**，是人类伙伴给的数。它只影响观感，
   不影响任何结论；但它确实让"点了激活要等一会儿"变成一件**被设计过的事**。
3. **环的旋转速度仍是白天定的 2.4 s/圈**，没有跟着新的 3–7 s 调。
   要不要让环转得与总时长成比例，没有讨论过。
4. **`busyPhase` 是新增字段，`LicenseState` 的 `ready` 那一支因此多一格**。
   仓库里所有构造 `LicenseState` 的地方（产品 1 处、测试 12 处）都已补上；
   但这是一处**结构变更**，将来若有人从别处构造这个状态，会先撞 TS 编译错 —— 那是好事。
