## 1. 拆掉的桌面采样（裁定 2 的执行半边）

删干净，不是留着不用：`electron/main/env-backdrop.ts`（152 行状态机）、`src/renderer/hooks/useBackdrop.ts`、`tests/unit/env-backdrop.test.ts`（6 条用例）、`shared/types.ts` 的 `BackdropFrame` 与 `DeepCleanApi.onBackdrop`、`electron/preload/index.ts` 的订阅实现、`shared/constants.ts` 的 `BACKDROP_EVENT_CHANNEL` + `BACKDROP_POLL_MS` / `BACKDROP_SETTLE_MS` / `BACKDROP_MIN_INTERVAL_MS`、`electron/main/index.ts` 的挂载点与 `detachBackdrop`、`App.tsx` 的 `useBackdrop()` 调用、`tokens.css` 的 `.dc-app::before` 与四个 `--dc-backdrop*` 变量。桌面能力本身已归零 —— 准确的命令与输出是 `git grep -nE "BackdropFrame|useBackdrop|BACKDROP_|dc:backdrop" -- electron src shared tests` ⇒ **只剩 `tokens.css:7` 一处注释**（讲的就是"它被删了"）。⚠️ 更正：我第一版写的是「`grep -rn "Backdrop"` = 空」，**那条命令实测非空 4 处** —— 3 处是本轮新加的 `topBackdrop`（`electron/main/index.ts` 里读 `backdropFilter` 的变量名），1 处就是上面那句注释。结论没错，引的命令与输出是假的，独立评审复算出来的。

**为什么是删而不是关**：留着它就是一条 250 ms 定时器，每 1.5 s 花 530 ms 去截一张 328 KB 的桌面图，而没有任何人消费。

**为什么它注定不对**（两条本机实测事实，随代码一起作废但值得留档）：① 那台状态机自己的判据是 `eligible = isVisible && !isMinimized` —— 截屏时本窗口必须可见，而 `desktopCapturer.getSources({types:['screen']})` 截的是**整块屏**，所以那张"背景"里必然含 DeepClean 自己的界面，糊 29 px 之后读起来是重影而不是壁纸；② `win.on('moved')` 在 Windows 上根本不触发（Electron 44.2.0 实测只有 focus/minimize/restore 真的来），"停止移动时截一次"只能做成轮询 + 去抖，那与"事件驱动"的原意已经差了一层。

真机截图（不带 `--shot` 的那一跑）把①拍了出来：右侧半屏是一团糊成竖条的自家窗口结构，首页那行占位文案「扫描完成后这里会给出可清理评估」在浅灰鬼影上几乎读不出来。拆掉之后同一行清晰。**这一条只有把窗口开在真桌面上才看得出来** —— `--shot` 按设计不挂截屏器，40 步判据一路零红，而从没看过玻璃长什么样。

## 2. 抓到并修掉一条已提交的缺陷：地图被玻璃的豁免整个盖住

**现象**：`tmp-shots/03-map-root.png` 的地图区，169 个采样点（PowerShell `System.Drawing` 读 PNG，x 15%–70% × y 15%–85% 网格）**全部是 `rgb(32,32,36)`**，也就是 `--bg` 一个颜色，一像素格子都没有。同一时刻 40 步判据零红，且命中测试照样取到坐标（`[shot] 34 文件格 => {"x":459,"y":454,...}`、`[shot] 24 目录格 => {"x":653,"y":454,"name":"Local"}`）。

**根因**（两处错叠在一起）：`.dc-treemap` 里叠着**两个** `.dc-canvas`（`TreemapCanvas.tsx:246` 底色层、`:249` 交互层），两者在 `global.css:351` 都是 `position:absolute; inset:0; width/height:100%`，交互层盖在底色层上面。`fb55e3c` 写的豁免是 `.dc-canvas { background: var(--bg) }` —— 它同时命中交互层，于是那张不透明板子把画好的格子整个盖掉。而它本来想保护的容器写成了 `.dc-map-wrap`，**全仓（global.css 与所有 .tsx）查无此类**，真名是 `.dc-treemap`。名字写错的那一半没生效，名字写对的那一半生效在了错的东西上。

**修复**：不透明底色移到 `.dc-treemap`；`.dc-canvas` 只留 `filter: none` + `backdrop-filter: none` 两道守卫；`::before/::after` 的 `content: none` 同时覆盖容器与两层 canvas。修完 `03-map-root.png` 的 169 点全变 `rgb(47,158,121)`（格子绿），`08-map-contextmenu.png` 出现 11 种颜色。

**两处被推翻的判据（评审复算出来的，都是我的错）**：
1. ~~`baseColors === 0` 时报「取不到 2d 上下文」~~ —— **恒不成立**：`colors` 初值 `-1`，而上下文一旦拿到，九次 `seen.add` 必得 ≥1，取值域是 `{-1} ∪ [1,9]`。于是"判据没跑成"这个元守卫是死代码，`getContext` 返回 null 时会掉进 `else if (<2)`，报成「格子根本没画出来」，**把下一个人送去查地图绘制**。现在 `-1` 单独点名。
2. ~~九点采样数"颜色种数 ≥ 2"~~ —— **两条都错**：(a) 抓不到本闸声称要抓的缺陷 —— `getImageData` 读的是底色层**自己的缓冲**，交互层铺不透明板子发生在**合成阶段**，不碰这份缓冲；(b) 它过绿灯是**巧合** —— 评审用 PowerShell 复算 `03-map-root.png`，九个采样点里只有正中那点落在 tile 边框上（`rgb(33,45,44)`），其余八点全绿，视野被一个大格子占满时（放大后、单一主目录）它只有一种颜色，会**假红**。换成数 alpha 覆盖点之后：`painted=7`（九点里 7 点被画过），阈值 5 留了余量。

3. 追加 `.dc-main { filter: saturate(1.1) }` + `.dc-app::before { content: "ghost" }` → ⑥⑦ 各自点名（`dirty=dc-main filter=saturate(1.1)...`、`before="ghost"`），`shot_exit=1`。这一场还顺带暴露：那层全局覆盖贴片会让**另一会话正在写的 §41 判据②**（未装残留对不上夹具）跟着红 —— 它的读数对"上面盖了一层东西"敏感，已转告，不在本轮改动范围。

⚠️ **而且我第一版把方向做反了**（独立评审抓的）：给成 `menu .8 < card .86`，而计划书给菜单那档的理由原话是「不透明度需**明显高于**卡片，否则菜单内容会被背景干扰」—— 菜单恰恰是浮在地图上、文字最多的一层，且它是从 `global.css` 原值 `.97` 降下来的。实测影响：主文字 `#eaeaea` 对绿 tint 底仍有约 9:1（读得清，所以不是"坏了"），但次级文字 `.dc-menu-note` 与置灰项的 `#6b6b74` 从约 2.7:1 掉到约 2.1:1。现已对调回 `--glass-fill-card: .86` / `--glass-fill-menu: .92`（菜单 > 卡片，与计划书同向），换算说明写进 `tokens.css` 的 token 注释里。
