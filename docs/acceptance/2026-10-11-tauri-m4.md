## 1. 四个必答问题的结论

| 问题 | 结论 | 判据 |
| --- | --- | --- |
| 错码怎么办？ | **拒绝**（`InvalidCode`），且**不写任何文件** | `wrong_code_is_rejected_and_writes_nothing`、`empty_or_whitespace_code_is_rejected` |
| 同一个码在第二台机器上还能不能激活？ | **能** —— 完全离线的边界，无法拒绝 | `same_code_activates_on_two_independent_devices_offline`（**故意断言这个限制**） |
| license.dat 拷到另一台机器是否失效？ | **失效**（`DeviceMismatch`） | `copied_license_is_rejected_on_another_device` |
| DPAPI 加密-解密往返？ | **通过**；篡改密文/明文种子即拒 | `device_key_survives_dpapi_roundtrip_via_disk`、`tampered_ciphertext_fails_to_unlock`、`plaintext_seed_is_not_accepted_as_a_key_file` |

外加：幂等（同码重复激活 `AlreadyActive` 且不重写）、换码重绑、缺表 fail-closed、
签名被改 `BadSignature`、签名有效但码不在表里 `CodeNotInTable`、`status` 只读（不生成密钥）。

## 3. 未封口清单（M4 端到端还差什么）

### 3.1 那 1000 个真激活码不在这里（**最大的缺口**）

源码与文档**不含任何真码**。码表是**注入的数据**：运行时从外部载入 `codes.sha256`。
本仓库里只有**夹具**（`tests/data/codes.fixture.txt` 的 5 个 `DC-FIX-*` 假码 + 其清单）。
真码必须由用户提供，跑
`node src-tauri/crates/license/tools/gen-license-codes.mjs --from <真码清单> --out codes.sha256`。
**不要把夹具当成那 1000 个码来宣布授权范围。**

### 3.2 「重复激活码被拒绝」的可行边界

完全离线下的「拒绝」只覆盖三条：表内重号、表外错码、同机重复不产生第二份。
**跨机复用同一码无法拒绝**（无全局登记处）。规格验收行这条在此边界内成立，超出部分
必须如实告知用户，不能含糊成「已拒绝」。

### 3.3 清单一旦交付不可删码

`status` 会核对 license.dat 的 `code_hash` 是否在清单里（fail-closed）。代价：**已交付的清单
里不能删码**，否则已激活用户会当前失效。这是运维纪律，写进了 `activate.rs` 头注释。

### 6.2 界面契约（新增，此前不存在）

- `dc_license_status` → `{ state, activatedAtMs, deviceId, problem, problemReason }`
  `state` ∈ `licensed` / `unlicensed` / `invalid`；`invalid` 的 `problem` 是六个具名机器码之一
  （`no-device-key` / `license-unreadable` / `device-mismatch` / `bad-signature` /
  `code-not-in-table` / `table-unavailable`），各配一句中文原因。
  **非 `licensed` 一律 `activatedAtMs: null`** —— 不可信的记录不许带时间戳。
- `dc_license_activate` → `{ outcome, activatedAtMs, deviceId }`，`outcome` ∈ `activated` / `already-active`
  （幂等那条报的是**原来那次**的时间）。
- 失败 → `Err("E_…: 原因")`，四条稳定码：`E_LICENSE_TABLE` / `E_LICENSE_INVALID_CODE` /
  `E_LICENSE_DEVICE_KEY` / `E_LICENSE_FILE_WRITE`，外加这一层自己的一条 `E_LICENSE_DIR`
  （授权目录建不出来）。**缺表与错码分家**：把「清单没交付」报成「激活码无效」会让用户
  对着抄了三遍的码怀疑自己手抖。
- 三份文件同目录：`codes.sha256`（注入的交付物）/ `device.key`（DPAPI）/ `license.dat`。
  默认落在 `%APPDATA%\com.deepclean.app\license\`。

## 8. 改版：在线激活（2026-10-11，用户裁定）

> 用户原话：「离线认证改为在线激活（字面意思），用户输入激活码，点击激活，程序检测设备是否连接
> 网络，并检测网络是否可用，如果可用则激活成功，不可用则激活失败。」
> 以及随后那句更要紧的：「**本质还是离线激活，因为没有服务器验证，这个操作只是对用户的心理防御**。」

### 8.1 两条实话先写在最前面

1. **这道闸不增加任何授权强度**。没有服务器、没有登记处 ⇒ 能上网就能过，绕过的成本是零。
   它的作用在产品层（让"激活"这件事有一道真实存在的门槛），不在安全层。
   **文档、界面、以后任何一份简历都不许把它写成"在线验证授权"。**
2. 因此它的**风险方向是误伤，不是被绕过**：合法用户在公司防火墙 / DNS 挂了 / 代理白名单
   的环境里会被判"网络不可用"。三条设计都是冲着这个去的 ——
   探测点给三个（两个国内常用域名 + 一个**纯 IP** 223.5.5.5，这样 DNS 死了也还剩一条路）、
   失败时**逐条点名**哪个探测点为什么没应答、以及**状态查询永远不要求联网**
   （已激活的用户断网之后照样看得见自己的授权，否则这道闸就从"一次门槛"变成"随时能关掉软件的远程开关"）。

### 8.2 落在哪一层（这条决定了那些闸还成不成立）

探测住在**壳层** `src-tauri/src/netprobe.rs`，**没有**放进 `deepclean-license`。
理由：那个 crate 有一道随编译打红的结构性闸 `no_network_api_appears_in_this_crate`，
它的注释写着「完全离线是产品定义」。把探测塞进去只有两种收场 —— 删掉那条已被变异证明的边界，
或者让注释变成假话。所以：

- **crate 一字未改**（只在 `lib.rs` 加了一段说明改版与"本 crate 仍不联网"的界线），39 条判据照旧全绿；
- 网络判定是**进 crate 之前的一道前置条件**，不是授权判定的一部分 —— crate 看到的输入
  仍然是「码 + 路径 + 时间」，结论仍然只由码表与设备密钥决定；
- 顺序是判据：**闸门走在碰文件系统之前**。反过来（先调 crate 再判网络）会在没网的机器上
  留下一把孤零零的 `device.key`（crate 的写点在码校验之后）。

两条检测是两件事，错误文案因此分开：`E_LICENSE_NO_NETWORK`（本机没连任何网络，用一次
`UdpSocket::connect` 的路由查询判定，**不发一个包**）与 `E_LICENSE_NET_BLOCKED`
（连上了但出不去公网，TCP 握手到三个探测点全灭）。把前者报成后者，用户会去查一个没坏的防火墙。

### 8.3 界面文案改口（旧那句成了假话）

卡片那一行原先写「整个判定是离线的 —— 不联网、不上传」。现在激活会去建 TCP 连接，那句话不再成立，
改成：**「点「激活」时程序会先探测这台设备能不能连上公网：只向探测点建一条 TCP 连接，不发送任何数据。
探测通过才继续本机校验，并在这台机器的用户数据目录里写下两份文件（DPAPI 保护的设备密钥与授权记录）。
激活码不上传，也不删任何东西。」** —— 三句都是可核的：TCP 握手确实不带 payload、激活码确实只在本地做
SHA-256 比对、确实没有任何上传路径。

**没有加任何假装在连服务器的文案或假延时**。用户看到的门槛是真的（一次真探测），
但界面不谎称背后有一个验证方 —— 那是 §8.1 第 1 条的另一面。

`has_route()` 拆成参数化的 `route_ok(host, port)`，加一条判据：IPv4 socket 去连 IPv6 目的地，
任何 Windows 上都以 `Err` 告终 ⇒ `judge(false, ..) → NoLink` 这条路不再只是"代码写了没跑过"。

**这条不等于真拔了网线**：它证的是"拿不到路由时确实回 `Err`、确实被读成 `NoLink`"，
不是"没插网线那台机器上就是这个错"。真拔要动的是这台机器的网络适配器，那是会影响你正在做的事的动作，
我没自己动 —— 要关这一格，说一声，我写个"禁用→跑→立刻恢复"的脚本走一遍。

### 10.1 这一节补的洞不是"清单没生成"，是"清单到不了用户机器"

生成那一半早就有工具（`crates/license/tools/gen-license-codes.mjs --generate`）。真正致命的是另一件：

```
grep -rn "codes.sha256" 全仓库  →  只有三处：crate 里那个被注入的路径、service.rs 的目录布局、生成工具
```

**没有任何一环把它放到用户机器上。** 此前所有"激活成功"的证据都靠验收脚本自己
`Copy-Item $Table codes.sha256` 把**夹具**清单拷进授权目录（`m4-license-e2e.ps1:211`）。
也就是说链子断在最前面一环：**全新安装的用户哪怕手里拿着真码，也只会拿到
`E_LICENSE_TABLE`** —— 一个用户完全无法自证、也无法自救的错误码。这一节把那一环接上，
并且让它**在测试里就红，而不是等第一个用户点下去**。

### 10.2 那 1000 个码：形状、来源、放哪

| 坐标 | 值 |
| --- | --- |
| 生成命令 | `node src-tauri/crates/license/tools/gen-license-codes.mjs --generate 1000 --prefix DC- --codes-out D:/dc-license-vault/codes-2026-10-11-1000.txt --out src-tauri/resources/codes.sha256`（2026-10-11 跑的那一次就是交付的那一次） |
| 形状 | `DC-` + 32 位大写十六进制 = **35 个字符**（128 位熵，脚本内去重） |
| 明文清单 | `D:\dc-license-vault\codes-2026-10-11-1000.txt` —— **仓库外**，1000 行全部匹配 `^DC-[0-9A-F]{32}$`、`sort -u` 仍是 1000、行长只有 35 一种 |
| 哈希清单 | `src-tauri/resources/codes.sha256` —— **进仓**，1000 行 64 位小写十六进制、`sort \| uniq -d` 零重号。整文件 SHA-256 本次工作树上是 `cfe1bf5e6709…`，**但这不是个可跨机器引用的坐标**：仓库配了 EOL 过滤，换一次 checkout（LF↔CRLF）这个值就变。真正被机器判的不变量是「**投到磁盘的那份与编译期内嵌的那份逐字节相同**」（P2 与 Rust 判据各钉一遍），它两侧同口径，所以与 EOL 无关 |

**归一化契约换了一次独立口径**（不只看 node 自己算的）：改用 **PowerShell 的
`[Security.Cryptography.SHA256]`** 重算明文清单第 2 / 501 / 1001 行，三个哈希在清单里
`inManifest=1`；负对照 `DC-` + 32 个 `0` → `inManifest=0`。这一步的意义：crate 里那条交叉对账
（`fixture_manifest_agrees_with_rust_normalization`）只覆盖 5 条**夹具**码，真码的归一化
此前从未被第二个实现校过 —— 而那种错**只在真机上、只对拿真码的那个用户**现形。

### 10.3 投递形态的裁定：内嵌进二进制 + 首启落盘

三条理由与一条代价（都写进 `license_table.rs` 顶部，这里留结论）：

1. **判据落得了地** —— `include_str!` 让"随应用交付的那份表"变成单元测试逐字读得到的文件。
   走 `bundle.resources` 则要在打完包之后才验得到，而 `tauri.conf.json` 今天
   `bundle.active = false`，那条判据**没有载体**。
2. **不许诺不存在的授权服务** —— 本产品没有服务器（§8.1 那句实话），"运行时拉取清单"会暗示一个。
3. **离线首启也投得出** —— 网络那道闸只管点"激活"那一下，不该顺带决定清单到不到得了磁盘。

代价：**换一版清单要重新编译、重新发包**，且码**不能从表里撤销**。这与 crate 自己在
`activate.rs` 顶部记的「表一旦交付就不可从表里删码」是同一件事，不是新增约束。

落点只有一处：`main.rs` 的 `setup` 调 `service::materialize_code_table` → `license_table::ensure_at`。
**为什么走在两个命令之前**：`status` 也要读这份表（核对 `license.dat` 里的 `code_hash`），
只在激活前补一句会让已激活用户断网重开时读到 `table-unavailable`。
**为什么投递失败不拦启动**：授权目录写不下去（只读漫游配置、磁盘满）时把清理软件整个打不开，
是比"激活不了"更糟的降级；错误走 stderr，用户看得见的那一面仍是激活/状态上的具名错误。
**绝不覆盖已存在的那份**：那个位置是运维唯一的换表通道（`DC_LICENSE_DIR` 指过去），
覆盖它会让"谁放的表"事后无从考证 —— 宁可让畸形表以 `E_LICENSE_TABLE` 具名现形。

### 10.10 发布前判据：`scripts/license-leak-gate.mjs`（明文码不许以任何**文本**形态进仓）

§10.6 那次事故之后新增的一条，跑一次约 1 秒。**判据不是"形状对不对"，而是"这个串归一化后的
SHA-256 在不在随应用交付的那份清单里"** —— 因为形状 `DC-[0-9A-F]{32}` 在仓库里**合法地存在**：
`LicenseCard.tsx` 的占位符就是这一形制（一条编出来的示例码）。按形状一刀切会让这条闸一上线就红
在自己的正例上，然后被人加豁免、再然后就不看了。

```bash
node scripts/license-leak-gate.mjs   # exit 0 = 干净；1 = 有真码以文本形态进仓；2 = 判据自己坏了
```

本轮实测：

| 跑法 | 输出 |
| --- | --- |
| 直接跑 | `扫描 362 个文件（索引里另有 1 个已从工作树删除…；读不了 0）：形状命中 3，其中**在表里的** 0` → **exit=0** |
| **变异**：把明文清单第 2 行塞进 `docs/tmp-leak-probe.md` | `形状命中 4，其中在表里的 1` + `FAIL: … docs/tmp-leak-probe.md:8 DC-97BF86…55EFC` → **exit=1**（报错行自己做掩码，前 9 + 后 5 个字符） |
| 删掉那个探针文件再跑 | 回到 `在表里的 0` → **exit=0** |

三条防"恒真/恒假"的自检，都是被本轮踩过的坑直接逼出来的：

1. **覆盖面点名**（不是"文件数够不够大"—— 本仓真实规模是 363，写 500 会一上线就红）：
   清单本身、`LicenseCard.tsx`、夹具 `codes.fixture.txt`、脚本自己这四个路径**必须**在扫描集合里，
   少一个 exit=2。
2. **扫描器活着**：`LicenseCard.tsx` 至少贡献一条形状命中（`placeholderHits ≥ 1`）。
   形状命中为 0 一律判**判据坏了**，不许读成"真干净"。
3. **"已经不在了"与"读不了"分开**：`git ls-files -c` 会连工作树里已删、还没 commit 的旧哈希
   bundle 一起列出来，混成"读不了"就让这条闸每次改完 UI 假红一次。真·读不了的**文本**形制文件
