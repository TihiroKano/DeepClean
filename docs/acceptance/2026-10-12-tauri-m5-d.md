## 结论

开发环境页第一次跑在 Tauri 上，由 Rust 供数：九条 dev-cache 规则按生态分组，每行的

**扫描途中**的扩展名累加（不是从榜里数）。**全程零删除**：这一棒一行删除代码都没加，
也没点任何执行入口，跑完逐名点名六个夹具文件还在盘上。

## 1. 先翻一笔账：子代理那份变异电池不能采信

D1 的交付自带一份 `mutate.sh`，九条里六条报「红 0」，读起来像「那六条判据是摆设」。
实际是**脚本自己的分隔符**：它用 `|` 切字段，而锚点里就有 `|d|`、`||` 这类 Rust 闭包写法，
一裁就断，`APPLIED` 判定跟着错。拿单行锚点重跑，九条全部装得上，红了 2–6 条不等：

| 变异 | 装的是什么错 | 红 | 红了谁 |
| --- | --- | --- | --- |
| M1 | 三态塌两态：把「不知道」当「已装」 | 6 | 五条 view 判据 + 零容差对账 |
| M2 | 三态塌两态：把「不知道」当「没装」 | 6 | 同上（另一侧） |
| M3 | 残留空目录也端出来 | 3 | `an_unseen_territory_reports_no_residual` + 夹具覆盖度 + 对账 |
| M4 | 模型口径改成含 `.bin` | 3 | `dot_bin_is_deliberately_excluded...` + 名单三条 + 对账 |
| M5 | 计数挂错地方（每个分组都长出一格） | 2 | 夹具覆盖度 + 对账 |
| M6 | 命令可用性根本不问（只靠目录） | 6 | 四条两级判据 + 覆盖度 + 对账 |
| M7 | 「量不到」塌成 0 字节 | 2 | where 反证那条 + 对账 |
| M8 | 未装/不知道的行照样端出数字 | 3 | `unknown_status_is_never_a_number...` + 覆盖度 + 对账 |
| M9 | 拆掉 ENOENT 之后的 `where` 反证 | 3 | `absent_needs_both...` + 覆盖度 + 对账 |

两处要记的：

- **M4 原先根本装不上去**：往 `MODEL_FILE_EXTENSIONS: [&str; 8]` 追加 `.bin` 是 `E0308`
  （数组长度写在类型里）。「编译不过」不等于「钉住了」—— 改成**等长替换**（`.tflite` → `.bin`）
  才真的红了三条。读源码的名单判据（`!contains(".bin")` / 八项逐点名 / `len()==8`）这才被证明有牙。
- **一次自己造的假红**：电池还原用 `fs.copyFileSync`，而 Windows 的 `CopyFile` **保留源文件旧 mtime**
  ⇒ 还原后的源文件比变异那轮的构建产物还旧 ⇒ cargo 判定「没改」直接复用旧 rlib ⇒ 三条红
  （Docker `absent` 那一格整格丢）。`cmp` 已证明源码逐字节干净。**`cmp` 证明的是内容，cargo 看的是
  mtime，两者不是一件事。** 处置：还原后一律 `touch`，「还原后全绿」那一列整轮重跑。

## 2. golden 是独立口径产的，不是 Rust 自产自验

`tests/data/d1-parity.expected.json` 由 esbuild 把 TS 侧 `core/rules/detectors.ts` +
`core/rules/devenv-view.ts` + `core/analyze/model-files.ts` + `registry.ts` 打进 bundle、
node 跑同一份夹具产出。本棒按 `parity_devenv_ts.mjs` 头部那条命令**重跑一遍并与入库那份 `cmp`**：
**逐字节相同**。中间产物 `parity_devenv_ts.bundle.mjs` 当场删掉，不落仓。

`tests/readonly.rs` 那道静态闸同时守着「这一层零文件、零进程、零环境读取」：违禁形状是进程创建、
`std::fs`、环境变量读取、`which` 那类外部工具、`GetEnvironmentVariableW`，并且带**五条金丝雀**
证明针有齿（每条违例形状都真被扫到），还有一条证明 `#[cfg(test)]` 的切分真切开了。

## 4. 真机：三个独立口径，谁也不给自己作证

夹具 `D:\deepclean-fixture\m5d-scan`（`DC_ENV_ROOT` 把规则领地指进来、`DC_AUTOSCAN` 扫同一棵）：
三个权重（`.gguf` / `.safetensors` / `.pt`，共 3 670 016 B）+ 一个 4 MB 的 `data.bin` 诱饵 +
两条地盘文件（npm 8 192 B、maven 12 288 B）。

| 页面上那一格 | 独立口径 | 结果 |
| --- | --- | --- |
| 「检测到 3 个大模型文件（共 3.5 MB）」 | `Get-ChildItem -Recurse -File -Include <八项>` 的 `Count` / `Sum` | **3 / 3 670 016** 全等；`.bin` 没被算进来（算进来就是 7.5 MB） |
| 「从 7 个文件里数出来」 | `Get-ChildItem -File -Recurse \| Measure-Object` | 7 全等 |
| 「只数这些扩展名：… · 量的是 D:\deepclean-fixture\m5d-scan 这棵树」 | 名单是 crate 的原样回声 | 八项齐、**无 `.bin`**、根点名到位 |
| npm 行「已检测到 / 8.0 KB」 | PowerShell `Get-Command npm`（与应用的 `where` 是两套 API） | 两边都说装过；占用格 = 夹具地盘那份字节数 |
| Maven 行「未检测到 / 未检测到该工具」 | `Get-Command mvn` = False | 两边都没检测到，且那一格**没有塌成 `0 B`** |
| pip 行「这棵树上没有它的地盘（扫的是 …）」 | —— | 第三种 0 落到了句子而不是数字 |
| Docker 行 | `Get-Command docker` = False → 真起一次 df 得 `cli-missing`，再拿 `where` 反证 | 未安装 + 那句「只读查询，DeepClean 不代它清理 … `docker system prune`」，**没有一个删除控件** |

两张图都是**肉眼看过的**：侧栏「开发环境」是选中态（导航项按文字点进去的，不是 dev 入口切视图），
表头 分类/检测/占用/动作 四列齐，长句在「占用」列里换行没有压到右边的按钮。

顺带记两条脚本自身的错（都是"判据坏了"不是"应用坏了"）：
① 第一版在抓到页头那句之后**立刻**判定，而那一趟探测还没回来 ⇒ 红在「还停在正在问…」；
改成轮询到那句话消失。② `Wait-Substr` 的失败消息里 `Substring(0,260)` 在短文本上自己抛了，
把真正的失败原因吃掉；换成 `Peek`。

## 6. 已知分叉与代价（都点名，不含糊）

1. **两份 `ext_of`**（scanner 那一份、devenv 从 `pathutil` 翻的那一份）。由
   `dev_env::tests::the_two_ext_of_implementations_agree` 钉住：无分隔符语料逐字相等，
   含分隔符路径上「本份 ∘ 父名」等于 devenv 那份，并带一条反空跑（非空结果 ≥ 6 条，
   否则这条闸没有分辨力）。
2. **`error_hint` 截 240**：TS 数 UTF-16 单元，Rust 数 `char`；非 BMP 字符上差一两个，
   而这一格只进 `detail` 文案，不进任何判据。
3. **`ScanStatus::Idle` 在壳层不可达**：session 一出生就是 running，`idle` 那句话住在前端
   （`snapshot?.status ?? 'idle'`）。这里不补假档，补了「没扫过」与「扫完了」就共用一句话。
4. **Docker 每次现查**（最多 8 s），与 TS 同一分工；`installStatus` 进程级缓存一次。
   代价：反复进这一页会反复起 df。命令是 `async`，所以那 8 秒里窗口照常 repaint。
5. **`path_exists` 不带 `\\?\` 前缀**：超过 260 的模板路径会答「不在」，与 node 的
   `existsSync` 同方向（两边都答不出），不是新缺陷，但也不是能力。
6. **`dc_dev_env_view` 的返回校验只查顶层三键**：行里那些 `null`（没量过）与 `undefined`
   （这个生态不问）的分别是判据本体，桥里兜底等于把它们抹平。
