## 本版的偏离与边界（不许被读成"已满足"）

1. **磁盘上那份不是 §1.7 那张日志。** `core/clean/executor.ts` 的 **9 处** `log?.clean(...)`（数法：`grep -o 'log?\.clean(' core/clean/executor.ts | wc -l`）没有一处带 `risk=`（`grep -c risk core/clean/executor.ts` = **0**），而 §1.7 明写 `SIZE / RISK / STATUS / ERROR` 四栏；落盘的 `status=` 也只有 `success` / `failed` / `refused` 三种取值，`skipped` 与 `vanished` 在磁盘上都被写成 `refused`。所以五态与风险**只有内存视图给得出**。计划正文里我原先写「§1.7 的落盘这一半今天就已成立」，那句是错的，已由实现代理实测推翻并就地更正（提交 `dd9d7da`）。
2. **中文解释不落盘。** `detail` 只进内存条目，磁盘行只写 `errno`（失败）或 `reason`（拒绝）。所以页面上任何「详见日志文件」都不能承诺解释得清为什么被跳过。
3. **`ts` 是任务时间，不是删除时间。** 执行器不为每条路径读时钟（可复现性 + 不给 200k 条删除白加 20 万次系统调用）。代价：跨午夜的长任务整批归到起始那一天。按日筛选不受影响。
4. **记录页是会话内存视图，重启即空。** 它不是历史数据库，页面必须自己声明这一点并给出日志文件路径。
5. **`error` 一栏是混装的**（失败放 errno，跳过/消失放去掉 `**` 的中文句子）。裁定：不加第 9 个字段 `reason`（§1.7 只要 `ERROR`，按原因分组今天没人要过）；作为交换，那一列的表头必须写「详情」而不是「错误码」，且任何筛选谓词都不许去匹配它的字符串内容 —— 那正是裁定 2 明令禁止的「把事实源建在中文上」。
6. **未认领路径在 `task.status !== 'cancelled'` 时被静默丢弃**，且这条已被 `tests/unit/clean-journal.test.ts:294「status 不是 cancelled 时不许凭空造出 cancelled 条目」` 锁成期望行为。今天执行器产不出这种数据（`task.status` 只有 `refused`/`running`/`cancelled`/`completed` 四个赋值点），但 §1.8 第五条「所有删除动作均可追溯」的对账不该依赖"上游永不产坏数据"。

## 更正一条：判据③验的是"两个数相等"，不是"磁盘真省了多少"

V0.6 Task 5a 复审时我亲自复跑了靶场并发现 **§19 的 `actualFreedBytes` 与 `predictedFreedBytes` 都是"逐路径表观大小之和"**（`measureRoot` 复用 Scanner 按路径累加，`executor.ts:418`），两边同口径所以 `deltaBytes = 0`。有硬链接参与时预览已改对（33,554,432），而 §19 三个数全是 67,108,864，唯一说真话的是卷可用空间变化 33,456,128。

于是本文里判据③那句话要按这个口径读：

- **它成立的部分**：`electron/main/index.ts` 那条硬判验的是「内存账本合计 == §19 那一格」，等式真的成立，且两侧同源，不会各自漂。
- **它不验的部分**：**"实际释放"这四个字在 §19 界面上指的不是磁盘真实占用变化**。所以判据③不能读成"证明了我们真省下这些字节"。
- 准确表述应是：「记录页合计 == `actualFreedBytes`（**两者同为逐路径表观大小之和，不含 inode 去重**）；磁盘真实占用变化看同一张卡片上的「可用空间」前后两格」。

**本版的判定结论不必推翻**：V0.5 那批靶场读数（Task 18：102,236,160 B / deltaBytes=0）用的全是独立副本，没有硬链接参与，所以那几个数是真的。这是**措辞与标签**的问题，不是数字错。

**但产品自己的文案会说谎，这条是缺陷不是措辞**：`core/clean/executor.ts:533` 那句「实际释放 X 与预估 Y 一致」、`src/renderer/pages/Cleanup.tsx:417` 那个「（完全吻合）」，在有硬链接时都是在把一个虚数宣布成已核实。更值得记的是 `executor.ts:22` 的文件头：它老老实实列了"簇大小、备用数据流、并发写都会造成差"，**唯独漏掉唯一会让它"不差"的那一种** —— 于是 `deltaBytes=0` 看起来比任何时候都可信。两个错口径互相印证，比单独一个错更容易被信。已列入 V0.6 半棒 2 必修（改文案与标签，不动判定语义）。
