# 2026-10-29 1.0.1 → 1.0.2：修首页全 0 的回归 + 设置页重排

**一句话结论**：1.0.1 把首页"这块盘"的口径改对了、却把「没扫过时该显示什么」改错了 ——
首次进入整块盘是全 0。这一版把它修成**两级口径**，并按人类伙伴要求重排设置页、改文案、
把保险机制从"内核静默夹住"改成"弹窗 + 自动拉回"。

## 1. 首页全 0：一个我自己引入的回归

**症状**（人类伙伴，1.0.1 装机后）：「首次进入应该默认显示 C 盘数据啊，怎么全是 0，
而且切换到 D 盘这个数值也不会换成 D 盘的值」。

后半句是 1.0.1 修的那个 bug 的反面 —— **修过头了**。

### 三版的口径，逐版点名

| 版 | `scannedRoot` 取什么 | 症状 |
| --- | --- | --- |
| 1.0.0 | `drives.find(d => d.root === root)`，`root` = 盘符下拉 | 扫了 D 盘、首页还画 C 盘 |
| 1.0.1 | `snapshot?.root ?? null` | **没扫过就全空**：环 0.0%、容量「—」 |
| **1.0.2** | `snapshot?.root ?? startTarget` | — |

三版的错法是同一个：**把一个两级的问题当成一级**。

正确的口径是两件事分开：

- **有快照** → 读 `snapshot.root`（"刚才真扫了哪"），下拉怎么改都不动它；
- **没快照** → 读 `startTarget`（"下次要扫哪"）。盘的容量来自 `listDrives()`，
  **与扫描无关**，从来没有"没扫过所以不显示"的理由。

1.0.1 之所以不敢用 `startTarget`，是担心"下拉改了、正在报扫描结果的那半张卡跟着跳"。
两级口径把这个担心消掉了：只要**有快照**就一律读快照。

### 判据

`tests/unit/home-drive-scope-and-settings-order.test.ts`（本轮新增，8 条）：

- 逐字钉 `const scannedRoot：string = snapshot?.root ?? startTarget`；
- **反面对照**：`?? null` 这个形状必须被挡住（那是上一版的错误修法）；
- Home 里不许再有 `scannedRoot === null ? undefined` 那个短路；
- 驱动盘查找必须"先精确、再盘符前缀"（自定义目录要靠后者找所在那块盘）。

**变异验证做了**：把 `?? startTarget` 改回 `?? null`，那 8 条里当场红 2 条
（报错原话是「少了右边那半，没扫过时首页会是全 0」）。还原后重新绿。

## 2. 设置页重排与文案（人类伙伴第二轮要求）

原话：「设置页面组件重新排序，第一个语言，第二个性能，第三个外观，第四个授权，第五个关于，
然后性能栏里面并行倍率改为删除速率，推荐字改为默认推荐，下面的小字取消，保险机制变为
倍率拉到阈值以外出现弹窗提示然后自动拉回到阈值（当前设备上限，不崩溃）倍率」。

| 要求 | 落点 |
| --- | --- |
| 顺序：语言 → 性能 → 外观 → 授权 → 关于 | `Settings.tsx` 的 JSX 顺序 |
| 「并行倍率」→「删除速率」 | `t('删除速率')` |
| 「推荐」→「默认推荐」 | `t('默认推荐')` |
| 下面的小字取消 | 两段 `dc-fineprint` 整段删除 |
| 拉到阈值外 → 弹窗 → 自动拉回 | `PerformanceCard` 的 `onChange` |

**顺序为什么是这个**（写进代码注释了）：语言第一是因为它决定**后面四块怎么读** ——
一个看不懂中文的人打开这一页，第一个要找的就是它。其余四块按抽象层级往下排。

### 阈值从哪来

新增一条 IPC `dc_hardware` → `{ logicalCores }`。

**为什么不用 `navigator.hardwareConcurrency`**：那是 WebView2 那个进程看到的数，
与 Rust `available_parallelism` 不是同一个来源，在开了 CPU 组的机器上会给出两个不同的
答案 —— 而两个答案就是两套真相。判据里有一条 `not.toContain('navigator.hardwareConcurrency')`
钉着这件事。

**读不到时回 `{ logicalCores: 1 }`**（最保守那一档）：这一格读不到核数不该让整页设置白屏。

### 保险机制的三个细节

1. **滑块 `max` = 阈值**，所以"拉到阈值之外"在物理上就是"拉到头"——
   `<input type=range>` 到不了 `max` 之外。把它当成"想再往上"来处理。
2. **拉回的目标是 `SCAN_WORKERS_AUTO`（默认推荐）**，不是 `ceiling - 1`：
   人类伙伴要的是"自动拉回阈值"，而默认推荐就是这台设备稳定跑得动的档位。
3. **内核那道 `clamp_workers`（核数 ×2）一个字没改**。它守的是手改 `settings.json`
   的入口，与本页的交互是**两层**。界面这一层的 `max` 挡不住手改文件。

## 4. 没做的（如实登记）

1. **装机验收仍然没跑**（要 UAC，待点头）。
2. **首页的修复只在判据层验过，没在**真窗口**上看到**。判据钉的是那一行口径与
   Home 的查找链；「首次进入真的显示 C 盘 77.2 GB」要开窗口才看得见。
3. **设置页的重排与弹窗没截图**。8 条判据覆盖了顺序、文案、阈值来源、弹窗三要素，
   但"弹窗在真窗口里长什么样、会不会被 `.dc-card` 的 `backdrop-filter` 压住"没验 ——
   那正是我把弹窗写成 `position: fixed` + `z-index: 200` 的理由，但仍需肉眼确认一次。
4. **`dc_hardware` 只报了 `logicalCores`**。将来若"推荐档"改成核数的一半，
   那个决定属于产品，不该塞进这个命令（一个字段只装一件事）。
