## 三、需要你裁定的四件事

### 3.1 验收文档一份都不传？

上面按「只传程序相关」把 `docs/` 全排除了。但 `docs/acceptance/` 的正文（57 份 md，**0.75 MB**）
是**这个项目最有辨识度的东西** —— 每一条都写了「判据是什么、变异验证过没有、留下什么没做」。
传它（不传那 97.83 MB 的图）只多 0.75 MB。

**断链影响比预想的小得多**：57 份文档里只有 **3 份**用了 `assets/` 链接，一共 **8 条**
（其余 54 份是纯文字判据）。所以不传图只影响 8 个链接，其中 **1 条现在就已经是断的**
（工作区里就缺那张图）。处理办法：把那 3 份里的链接改成纯文字说明，或在文档头注明
「图不在本仓」。**不建议留断链不管** —— 那看起来像仓库坏了，而不是像刻意省略。

### 3.2 `src-tauri/dist/` 传不传？

它是**前端构建产物**（18 个文件，0.3 MB），但**必须传**：`tauri::generate_context!` 在编译期
把它嵌进二进制，`.gitignore` 里专门写了 `!src-tauri/dist/**` 两行来放开它。0 个文件被跟踪 =
从克隆里 build 出来的 exe 没有界面。

所以它不是"产物"，是**源**。

### 3.3 `codes.sha256` 传不传？

它是 **SHA-256 哈希清单**，反推不出明文码，进仓是刻意的（`license_table.rs` 靠
`include_str!` 嵌它）。**不传的话从克隆里 build 出来的程序激活不了任何码。**

建议传。真正的敏感物是明文清单 `codes-2026-10-27-1000.txt`，它在 `D:\dc-license-vault\`，
`.gitignore` 的 `codes-*` 挡着，**不在库里**（已验证）。

### 3.4 仓库要不要另起一个干净的初始提交？

现在有 1000+ 条历史（含一次 `git bundle` 做过的历史抹除，那次处理掉 66 张整屏截图）。
如果只想要「1.0.0 的代码」而不要这一个月的过程记录，可以另起一个 orphan 分支只放
396 个文件，提交历史从 1 条开始。

**代价**：所有「为什么这么写」的上下文只剩代码注释。本仓的注释密度很高，所以损失可控，
但那些 commit message 里确实有决策依据（比如为什么 `asInvoker` 改回 `requireAdministrator`）。
