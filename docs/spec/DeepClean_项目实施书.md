# C盘深度清理与智能磁盘分析工具

## 项目实施书 / Product & Technical Specification

**项目代号：** DeepClean\
**项目类型：** Windows 桌面应用\
**目标平台：** Windows 10 / Windows 11 x64\
**核心技术方向：** Electron + React + Node.js\
**核心能力：** 磁盘空间扫描、Treemap
空间可视化、垃圾识别、大文件分析、重复文件检测、安全清理

------------------------------------------------------------------------

# 一、项目概述

## 1.1 项目背景

Windows 用户在使用电脑一段时间后，C 盘容易出现空间不足的问题。

传统磁盘清理工具通常存在两个问题：

1.  只能清理预定义的垃圾文件；
2.  无法直观告诉用户"究竟是什么占用了 C 盘"。

因此，本项目计划开发一款现代化 Windows 磁盘分析与安全清理工具。

项目首先通过高性能文件系统扫描器对指定磁盘进行完整分析，并采用类似
SpaceSniffer 的 Treemap 空间可视化方式，让用户能够直观看到：

> 哪个目录占空间、哪个文件占空间、空间具体分布在哪里。

在此基础上进一步增加：

-   垃圾文件识别
-   缓存分析
-   大文件分析
-   重复文件检测
-   开发环境缓存分析
-   清理风险等级
-   清理前预览
-   清理记录
-   清理报告

最终形成：

> **扫描 → 分析 → 判断 → 预览 → 清理 → 验证 → 报告**

的一体化 Windows 磁盘管理工具。

-   支持继续深入目录

-   支持空间占用排序

# 三、产品定位

DeepClean 不定位为传统的"一键垃圾清理软件"。

核心定位：

> **Windows 磁盘空间分析 + 安全清理工具**

产品价值分为三层。

### 第一层：看清楚

回答：

> "我的 C 盘到底被什么占满了？"

通过 Treemap 展示空间分布。

### 第二层：判断

回答：

> "这些东西哪些可以处理？"

通过规则引擎进行：

-   文件分类
-   缓存识别
-   风险判断
-   可清理空间计算

### 第三层：处理

回答：

> "怎么安全释放空间？"

通过：

-   清理预览
-   风险分级
-   用户确认
-   清理任务
-   清理结果验证

完成安全清理。

# 五、SpaceSniffer 级扫描器

这是整个项目的第一优先级。

## 5.1 扫描模型

扫描器采用：

``` text
Drive
 ↓
Directory
 ↓
SubDirectory
 ↓
File
```

最终形成树状数据结构：

``` text
C:\
├── Users
│   ├── Kano
│   │   ├── AppData
│   │   ├── Downloads
│   │   ├── Desktop
│   │   └── Documents
│
├── Windows
│   ├── System32
│   ├── WinSxS
│   └── Temp
│
├── Program Files
├── ProgramData
└── $Recycle.Bin
```

每一个节点保存：

``` text
id
name
path
type
size
fileCount
directoryCount
modifiedTime
parentId
children
```

其中：

``` text
type = file | directory | drive
```

# 六、扫描器性能要求

不能采用简单的：

``` text
扫描一个文件
↓
等待完成
↓
扫描下一个文件
```

而应该采用异步并发扫描。

推荐：

``` text
Scanner
   │
   ├── Worker 1
   ├── Worker 2
   ├── Worker 3
   ├── Worker 4
   └── Worker N
```

但是并发数量必须受到限制。

目标：

> 在保证系统稳定性的情况下最大化磁盘读取效率。

不能为了追求速度把磁盘 I/O 拉满导致：

-   系统卡顿
-   Explorer 卡顿
-   游戏掉帧
-   SSD 长时间高负载

------------------------------------------------------------------------

# 七、增量结果机制

扫描过程中不能等全部扫描完成以后才显示结果。

应该：

``` text
开始扫描
 ↓
发现 Users
 ↓
立即显示 Users
 ↓
发现 Downloads
 ↓
更新 Downloads
 ↓
发现 AppData
 ↓
更新 AppData
```

UI 实时变化。

例如：

``` text
正在扫描 C:\Users\...

已扫描：
1,283,492 个文件

当前扫描：
C:\Users\...\AppData\Local\...

已发现：
82.3 GB
```

这样用户能够感受到软件正在真正工作。

# 八、权限处理

Windows 文件系统存在大量无法访问的目录。

例如：

-   System Volume Information
-   某些 Windows 系统目录
-   其他用户目录
-   被程序占用的文件

遇到无法访问的路径时：

**禁止导致整个扫描任务失败。**

处理流程：

``` text
Try Scan
   ↓
Success → Continue
   ↓
Access Denied
   ↓
Record Error
   ↓
Skip
   ↓
Continue
```

最终显示：

``` text
扫描完成

扫描文件：1,283,492
扫描目录：82,341
跳过项目：327
权限错误：41
```

# 十六、安全等级

所有清理项目必须具有风险等级。

### 🟢 安全

例如：

-   用户 Temp
-   浏览器缓存
-   Shader Cache
-   缩略图缓存
-   部分日志

### 🟡 谨慎

例如：

-   npm cache
-   pip cache
-   Gradle cache
-   Docker 未使用数据

### 🟠 高风险

需要明确提示：

> 清理后可能导致软件重新下载数据或重新生成缓存。

### 🔴 禁止

例如：

``` text
System32
WinSxS
Windows Installer
关键系统组件
```

禁止通过普通清理按钮直接删除。

# 二十、重复文件检测

采用两阶段策略。

### 第一阶段

根据：

``` text
文件大小
```

建立候选组。

### 第二阶段

对候选文件计算：

``` text
Hash
```

推荐：

``` text
快速 Hash
 ↓
候选重复组
 ↓
完整 Hash
 ↓
确认重复
```

避免整个 C 盘无脑计算 Hash。

结果：

``` text
发现重复文件

example.zip

C:\Downloads\example.zip     2.8 GB
D:\Backup\example.zip        2.8 GB
C:\Desktop\example.zip       2.8 GB

总占用：8.4 GB
理论可释放：5.6 GB
```

# 二十八、安全设计原则

这是本项目最高优先级。

### 原则一

**扫描 ≠ 删除**

扫描器永远不能自动触发删除。

### 原则二

**系统文件默认保护**

### 原则三

**所有清理行为可预览**

### 原则四

**清理范围明确**

例如：

``` text
C:\Users\xxx\AppData\Local\Temp
```

而不是：

``` text
AppData
```

### 原则五

**删除失败不能导致程序崩溃**

### 原则六

**永远允许用户取消**

# 三十五、项目第一验收标准

第一阶段不看 UI 漂不漂亮。

只看四件事情：

### 1.

能不能扫描真实 C 盘。

### 2.

能不能正确统计目录大小。

### 3.

能不能处理大量文件而不冻结 UI。

### 4.

能不能通过 Treemap 快速找到真正占空间的位置。

如果这四点做到：

> **第一阶段通过。**

然后再开始做清理。

# 三十六、项目开发原则

整个项目遵循：

> **先扫描，再分析；先分析，再清理；先保证安全，再追求功能；先保证正确，再追求漂亮。**

尤其禁止为了"看起来能清理很多空间"而采用危险删除策略。

DeepClean 的核心不是：

> "帮用户删掉更多东西。"

而是：

> **"让用户准确知道 C 盘发生了什么，并安全地释放真正可以释放的空间。"**
