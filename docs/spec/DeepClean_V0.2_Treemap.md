DeepClean V0.2 开发目标

一、版本定位

版本：V0.2

核心目标：

将 V0.1 文件扫描引擎产生的目录树与文件大小数据，转换为可交互的 Treemap 空间地图，实现 C 盘空间占用的直观可视化与目录逐级分析。

V0.2 暂时不实现文件清理。

本版本重点验证：

* 扫描数据是否正确
* Treemap 是否能够准确表达空间占用
* 大目录是否能够快速定位
* 用户能否通过地图快速找到 C 盘空间占用来源

⸻

二、V0.2 核心功能

1. C 盘空间地图

启动扫描完成后自动进入空间地图。

Treemap 中：

* 矩形面积 = 文件 / 文件夹占用空间
* 文件夹 = 一个区域
* 文件 = 区域中的子块
* 文件越大，矩形越大
* 文件夹越大，占据的区域越大

例如：

C:\
┌──────────────────────────────────────────────┐
│                                              │
│                    Users                     │
│                   86.4 GB                    │
│                                              │
│                                              │
├────────────────────────────┬─────────────────┤
│                            │                 │
│      Program Files         │    Windows      │
│          42.7 GB           │     28.6 GB     │
│                            │                 │
├────────────────────┬───────┼─────────────────┤
│ ProgramData        │ Temp  │ Other           │
│ 18.5 GB            │ 7.2GB │ 5.8 GB          │
└────────────────────┴───────┴─────────────────┘

⸻

三、目录层级浏览

Treemap 必须支持逐级进入。

例如：

C:\
 ↓
Users
 ↓
用户名
 ↓
AppData
 ↓
Local
 ↓
Packages
 ↓
某个应用

每进入一级，Treemap 都重新计算当前目录内部的空间分布。

⸻

四、面包屑导航

地图顶部显示当前位置：

C:\  >  Users  >  Kano  >  AppData  >  Local

点击任意一级即可返回。

例如点击：

C:\ > Users > Kano

直接返回 C:\Users\Kano。

⸻

五、点击交互

单击一个区域：

显示该项目的信息。

例如：

文件：42,831
目录：1,204
路径：
C:\Users\Kano\AppData\Local\Microsoft

六、双击进入

双击目录：

双击文件：

十一、颜色系统

V0.2 不需要复杂渐变。

首先保证：

不同层级能够清楚区分。

建议：

系统目录      → 蓝色系
应用程序      → 紫色系
用户数据      → 青色系
缓存          → 黄色系
普通文件      → 中性色

注意：

颜色主要用于分类和层级识别。

不能让颜色喧宾夺主。

例如：

Treemap
↓
实时刷新
↓
目录大小逐渐准确

最终扫描完成后锁定结果。

⸻

十五、异常数据处理

Treemap 不能因为某个文件访问失败而崩溃。

例如：

Access Denied
File Not Found
File Locked
Path Too Long

统一处理：

跳过文件
记录错误
继续绘制其他数据

地图中可以显示：

部分数据无法访问
共跳过：128 个文件

⸻

十六、性能目标

V0.2 必须保证地图不会因为文件数量太多而卡死。

重点测试：

10,000 文件
50,000 文件
100,000 文件
500,000 文件
1,000,000+ 文件

目标：

* Treemap 计算不阻塞 UI
* 页面保持可交互
* 大目录进入速度可接受
* 不一次性创建几十万个 DOM 元素
* 优先使用 Canvas / WebGL 等高性能绘制方式
* 避免 React 为每一个文件创建独立组件

⸻

十七、数据结构

V0.2 直接使用 V0.1 Scanner 输出的数据。

基本结构：

Node
id
name
path
type
size
fileCount
directoryCount
modifiedTime
parentId
children

其中：

type =
drive
directory
file

Treemap 不应该自己重新扫描文件。

数据来源统一：

Scanner
   ↓
Scan Result
   ↓
Analyzer
   ↓
Treemap

⸻

十八、技术实现建议

推荐：

Electron
+
React
+
TypeScript
+
Canvas / WebGL Treemap

Treemap 算法可以采用：

Squarified Treemap

目标是尽可能让矩形接近正方形，提高可读性。

基本原则：

文件大小
   ↓
面积权重
   ↓
Treemap Algorithm
   ↓
矩形坐标
   ↓
Canvas 绘制

⸻

十九、V0.2 暂时禁止加入

为了防止项目膨胀，本版本明确不做：

* 文件删除
* 自动清理
* AI 分析
* 重复文件检测
* 缓存识别
* 清理规则
* 云端同步
* 用户账号
* 自动优化
* 系统注册表清理

这些全部放到后续版本。

⸻

1. 扫描 C 盘
2. 获得完整空间地图
3. 看到最大目录
4. 看到最大文件

二十一、V0.2 完成后的意义

V0.1 是：

“我能扫描 C 盘。”

V0.2 是：

“我能让用户一眼看懂 C 盘空间到底去哪了。”

这一步完成后，DeepClean 才真正具备自己的核心产品形态。

下一版本 V0.3 再接：

大文件智能分析 + Top 100 + 文件类型统计 + 空间异常发现。
